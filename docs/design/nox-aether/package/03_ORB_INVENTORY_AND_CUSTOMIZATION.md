# AETHER / ORB LIBRARY + PERSONALIZATION

## Абсолютное требование — две сферы неприкосновенны

В Nox уже существуют **две одобренные владельцем сферы: «точечная» и «синяя»**. Из скриншотов и названий нельзя надёжно установить однозначное соответствие файлам — **Fable/Opus обязаны лично найти оба живых варианта в проекте и подтвердить визуально**. Не переименовывать/объединять их по догадке. Не переписывать shader, Canvas/WebGL, геометрию, анимацию, энергетику, состояние, FPS-профили, параметры двух оригиналов.

Исходная карта потенциальных реализаций (`AGENTS.md`, проверять актуальность): `renderer/orb.js`, `renderer/orb-variants.js`, `renderer/orb-nox.js`, `renderer/orb-tune.js`, `renderer/nox-screen.js`.

Перед миграцией:
- Записать имена, entry points и текущие настройки обеих сфер.
- Снять отдельный проверочный скриншот на том же размере, что baseline.
- Сохранить существующие методы (`setVoice`, `setTune`, состояние, visibility pause) через adapter, не меняя исходники.
- После подключения через библиотеку сравнить визуально и проверить отсутствие двойного рендера.

## Библиотека сфер (инвентарь)

Экран: «Мастерская Nox» → «Сферы».

Карточка сферы:
- Название и статичный/разрешённый анимированный preview.
- Отметка «Оригинальная» для двух существующих.
- Кнопка «Выбрать» и состояние «Установлено».
- Возможности, которые реально поддерживаются данным вариантом (голос, плотность, цвет, скорость, качественный режим).
- Профиль производительности, честно измеренный.
- Сброс персональных параметров только этой сферы.
- Никаких платных/закрытых обещаний без серверного entitlement.

Новые сферы подключаются **отдельным адаптером/модулем**, не изменяя код других вариантов. Переключение должно освобождать старый Canvas, listeners и таймеры.

Возможный декларативный контракт (пример схемы, не обязательная реализация):

```ts
interface OrbVariantDescriptor {
  id: string;                   // уникальный стабильный ID
  title: string;
  origin: 'built-in' | 'optional';
  immutableOriginal?: boolean;  // флаг защиты двух существующих
  previewAsset: string;
  capabilities: Array<'voice'|'color'|'density'|'speed'|'intensity'>;
  defaults: Record<string, unknown>;
  createAdapter: () => OrbAdapter;
}
interface OrbAdapter {
  mount(container: HTMLElement): void;
  setSystemState(state: OrbSystemState): void;
  applySupportedTuning(tune: object): void;
  pause(): void;
  resume(): void;
  destroy(): void;
}
```

Если оригинал не поддерживает какой-то параметр, UI честно отключает его вместо подмены реализации.

## Deep customization / Мастерская Nox

### Раздел «Композиция»
- Сфера справа / слева / компактная / скрытая.
- Доли пространства: чат, история, сфера; разумные min/max.
- Режим: компактный, комфортный, просторный.
- Выбор, скрывать ли историю на узком экране.
- Автосмещение сферы при длинном ответе — **только если пользователь включил**.

### «Чат»
- Minimal / Cards / Hybrid; на реальном сообщении в превью.
- Размер шрифта, максимальная ширина текста, межстрочный интервал, расстояние между репликами, радиусы, отображение времени.
- Вид карточек инструментов (автосвёрнуты/компактны/расширены).
- Настройки движения потокового текста без появления ложного «набор текста человеком».

### «Цвета и фон»
- 11 существующих тем **сохранить**; поверх них собственный акцент, если это уже поддерживается.
- Один спокойный фон; градиент/контур/выбранное изображение.
- Тонкие границы; размытие и прозрачность с совместимостью.
- Персональные фото не уходят в сеть и не попадают в логи/историю.
- Собственный фон должен иметь «Сброс», не ломать контраст текста.

### «Сфера»
- Список исходных и новых сфер.
- Для поддерживающих вариантов: размер, свечение, движение, скорость, плотность и голосовая реакция.
- Не менять исходное поведение двух оригиналов при значениях по умолчанию.
- Preview без запуска двух тяжёлых Canvas одновременно.

### «Эффекты и производительность»
- Motion: off / reduced / balanced / expressive.
- Уважать Windows prefers-reduced-motion.
- Пауза рендера в скрытом/свёрнутом окне.
- Уменьшение DPR/частиц при снижении производительности (в настройках, не скрытое ухудшение originals).
- Ограничение частоты перерисовки фона.
- Тестовые FPS/CPU результаты отражать правдиво.

### «Мои оформления»
- Заводские пресеты + сохранение собственного.
- Превью → Применить → Отменить → Вернуть стандартное.
- Экспорт/импорт JSON с **строгой схемой и ограничениями**, без кода, скриптов, токенов, паролей, истории чатов или путей к приватным файлам.
- Версии настроек и миграции, защита от несовместимой/сломанный пресет.
- Отсутствие возможности установить права агента, unsafe mode или активировать новые инструменты через пресет оформления.

## Принцип безопасности персонализации

Внешний вид — данные с низким доверием. Пресеты не имеют доступа к IPC, не могут выполнять CSS/JS напрямую и не меняют backend security. Загруженный пользовательский фон валидируется по формату/размеру, не уходит в удалённые сервисы. Изменение внешнего вида **не должно** перезапускать агента, терять контекст, сбрасывать очередь подтверждений или активные задачи.

## Тесты двух оригинальных сфер

1. Каждый original доступен в инвентаре и отображается без изменения визуального базиса.
2. Из A в B и обратно — нет зависших timers/WebGL контекстов.
3. Переход в чат/настройки не запускает второй рендер.
4. Окно свернули → анимация ставится на паузу; вернули → корректно продолжается.
5. Voice state не течёт между вариантами.
6. Сброс пресета не повреждает baseline originals.
7. Новые сферы не ломают оригиналы и могут добавляться без правок их файлов.
