## Gate 1. Дизайн и прототипы — до одобрения владельца
Делегируй Fable **три принципиально разные** концепции реального окна Nox:

**A / Minimal Presence** — камерная композиция, сфера как главное присутствие, очень чистый чат, минимальная боковая навигация.

**B / Fluid Workspace** — живое переключение внимания между сферой и перепиской; действия сворачиваются в компактные слои, нет постоянной панели метрик.

**C / Spatial Dialogue** — необычное объединение сферы и разговорной области, но без потери читаемости и управления на малом экране.

Каждая концепция обязана показать одинаковые 6 сценариев: пустой чат; обычный диалог; длинный ответ Markdown/код; выполнение 8+ инструментов; запрос подтверждения; голос. И отдельно — экран «Мастерская Nox» с выбором сферы и кастомизацией.

**Выход:** 3 полноценных изображения на `1200×720`, адаптации `864×520`, плюс минимум один изолированный интерактивный прототип с реальными переходами на фиктивных данных (если ресурсы доступны). Указание, что именно демо.

Haiku проверяет варианты, Fable исправляет замечания. Максимум 2 цикла. Opus выбирает свой рекомендуемый вариант, **но последнее слово за владельцем**.

**СТОП: покажи три варианта и дождись выбора владельца. Никаких правок рабочего UI до этого.**

## Gate 2. Инженерная реализация — только после явного выбора
Fable строит **новую оболочку**, а не новый слой над старой. Подключение должно использовать существующие события/IPC/данные, не дублировать бизнес-логику. Старый UI изолируется как временный rollback, **новая оболочка не должна импортировать/наследовать его каскад CSS**. После паритета функциональности и разрешения владельца старую оболочку можно удалить/вывести из продукта.

Реализовать:
- Чат: идеальная типографика, сообщения и Markdown, ввод и вложения, потоковые ответы.
- Действия: компактные раскрывающиеся карточки, честная проверка результата, ошибки, стоп/отмена, approvals.
- Сферу: использовать одну из двух существующих оригинальных сфер через новый реестр вариантов, без изменения их внутренних файлов.
- Мастерскую: пресеты, режимы компоновки, масштаб, цвета, фон, стиль чата, анимации, лёгкий режим.
- Не внедрять новые уникальные 3D-механики, которые ухудшают читаемость или блокируют MVP. Nox Live и Verification Seal — после стабильного чата, если они основаны на реально доступных событиях.

Прогон целевых тестов, project-map.test.js, затем полного набора в согласованное окно (чтобы не конфликтовать с C5/C6/C7).

До полного прохождения не включать новый интерфейс по умолчанию у других пользователей. После явной приёмки владельцем переключить default и сохранить возможность отката до окончательного удаления legacy.
