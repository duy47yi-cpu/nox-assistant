# AETHER / VISUAL DESIGN SPECIFICATION

## 0. Контекст и эстетическая задача

Nox — **персональный автономный помощник для Windows**, в котором чат и сфера — единый живой интерфейс. Владелец отверг презентационные макеты с крупными таблицами, KPI, множеством статусных карточек и постоянно открытыми панелями мониторинга. Это не CRM, не Windows Dashboard и не точная копия Jarvis Pro.

Основная цель — чтобы окно выглядело **лёгким и узнаваемым**, а при длинных разговорах и сложной работе оставалось исключительно удобным. Тёмная палитра; точные расстояния; мягкие поверхности; одна выразительная сфера; спокойные анимации. Не делать чрезмерно мелкий текст только ради минимализма.

## 2. Устойчивые требования к визуальной системе

- **Одна точка внимания в состоянии ожидания:** исходная выбранная сфера.
- **Два равноценных фокуса в ходе диалога:** сообщения и сфера, без взаимного подавления.
- **Сложность по требованию:** детали инструментов и исполнения раскрываются кликом, а не заваливают переписку.
- **Честные статусы:** idle, listening, speaking, planning (если есть реальное событие), tool-running, awaiting-approval, verifying, success, failed, cancelled. Названия не должны раскрывать скрытые рассуждения модели. Не выводить фальшивый прогресс 84%.
- **Минимум фальшивого стекла и неона:** акцент сохраняется, но не заменяет читаемость.
- **Никакой путаницы между голосом и задачами:** реакция сферы на громкость только от реального сигнала, не постоянный декоративный фейк.
- **Акцент и стиль пользовательский:** пресеты/режимы, а не одно навязанное решение.

## 3. Новый чат: обязательные состояния

### 3.1 Диалог
- Пользовательское сообщение: компактная форма; длинное сообщение правильно переносится; редактирование/копирование/метаданные не занимают постоянную ширину.
- Ответ Nox: свободный текст без громоздкого пузыря; отчётливая иерархия заголовков, абзацев и списков; комфортная длина строки; обычный и длинный ответы одинаково удобны.
- Markdown: заголовки, маркированные/нумерованные списки, цитаты, таблицы с горизонтальной прокруткой, код с копированием, ссылки, встроенные формулы (если поддерживаются текущим движком), файлы и источники.
- Потоковая выдача: плавное добавление текста **без прыжка ленты**, корректное управление автопрокруткой; когда пользователь поднялся вверх, Nox не вырывает скролл обратно.
- Пустой экран: не заполнять виджетами; одна ясная фраза/возможность начать разговор и выразительная сфера.
- История: длинные названия не ломают сетку; видимое выделение текущего разговора; поиск и новая беседа остаются доступными.

### 3.2 Работа инструментов
- Компактный «ход задачи» внутри потока: краткое действие, статус и результат.
- Свернуть группу из 8+ инструментов до одной аккуратной записи; открыть подробности без изменения доверенного поведения.
- Проверка результатa: «проверено» только когда инструмент/политика реально прислали подтверждение. Отличать «создано» от «проверено» и «не удалось подтвердить».
- Ошибки и таймауты: ясная причина, понятное безопасное дальнейшее действие; не притворяться успешным выполнением.
- Отмена: остановка в UI не является доказательством остановки инструмента; отобразить честный статус по контракту бекенда.

### 3.3 Подтверждения
- Для рискованного действия — не просто «Разрешить», а краткое описание **что**, **где** и **какой риск**.
- Существующий approvalId / проверка аргументов / состояние очереди остаются собственностью backend security. Дизайн не меняет логику разрешений, не показывает кнопку, которая подтверждает не тот запрос.
- Клавиатура/показ ошибки/таймаут/отзыв — обязательно.

### 3.4 Поле ввода
- Устойчивое положение на больших/малых окнах.
- Многострочный ввод; прикрепление файлов и голос; отправка и остановка; индикатор выбранного режима; кнопки не исчезают при узком окне.
- Фокус, Enter/Shift+Enter (по действующему контракту) и видимый прогресс доступности.

## 4. Три визуальных направления (действительно разные)

### A — Minimal Presence
Сфера крупная и видна рядом с диалогом, но чат получает более широкую текстовую линию при заполнении. Навигация исчезает в сворачиваемую рейку. При ожидании больше воздуха, при диалоге акцент мягко переносится на текст.

### B — Fluid Workspace
Две зоны с **переключаемой композицией**: разговор и «живое присутствие». Никаких постоянных KPI. Детали исполнения открываются в ленте чата и коротком временном всплывающем слое. Панели умеют менять баланс ширины.

### C — Spatial Dialogue
Сфера и контент визуально образуют единую сцену без тяжёлой жёсткой границы. При длинном тексте сфера уменьшается или смещается, освобождая ширину, но сохраняет узнаваемость. Приоритет — контраст и доступность при 864×520.

**Во всех трёх** использовать одинаковые демонстрационные сообщения и состояния; необходимо сравнение эффективности, а не цвета.

## 5. Механики, но после базового чата

- **Nox Live:** краткие реальныe этапы текущей задачи, детальная карта только по запросу. Не постоянный правый дашборд.
- **Verification Seal:** маленькие маркеры проверенных действий на периферии сферы без визуальной перегрузки; доступ к проверке через связь с событием.
- **Trust Aperture:** исключительно индикатор действующего режима разрешений; сама анимация права не выдаёт.
- **Wallpaper Relief:** локальное преобразование картинки в мягкий рельеф, отключаемое, не читающее пользовательские обои без выбора файла.
- **Memory Landscape:** отложить до отдельного аудита приватности и UX. Никакого скрытого удаления/перезаписи памяти.

## 6. Кастомизация — проектировать вместе с чатом

Нужна «Мастерская Nox» в настройках: выбор библиотечной сферы, положение/размер, плотность текста, стиль сообщений, ширина диалога, световые эффекты, цвет, фон, шрифты, motion, быстрые пресеты, импорт/экспорт **настроек без секретов**. Подробно в `03_ORB_INVENTORY_AND_CUSTOMIZATION.md`.

## 7. Как выглядят готовые макеты

Для **каждого** концепта предоставить:
1. 1200×720 — пустой экран и короткий разговор.
2. 1200×720 — длинный ответ с Markdown и кодом.
3. 1200×720 — 8+ действий и одно подтверждение.
4. 864×520 — компактный layout того же разговора.
5. Мастерская с видимым выбором **двух исходных сфер**.
6. Обозначение настоящих данных и демо. Никаких фиктивных успехов без подписи «концепт».

**Критерий**: зритель узнаёт Nox, а не корпоративный трекер; пользователь умеет читать и управлять им.
