## 3. Что добавлено (только своя зона)

### `src/extensions/clipboard-history.js` (400+ строк)
- `ClipboardHistoryStore(filePath, options)` — один JSON-файл `{version, paused, ttlMs, items}`; каждая операция читает файл заново, два экземпляра на одном файле видят друг друга. Внедряются `fs`, `path`, `now`, лимиты `maxItems` (200), `maxText` (4000 кодовых точек), `maxTotalChars` (100000), `ttlMs`.
- `add({text, protected})` **не бросает** исключений: запись идёт на каждое копирование, поэтому нормальные отказы — это `{ok:false, saved:false, reason:'empty'|'protected'|'private'|'paused', message}`. Текст никогда не попадает в `message`.
- Приватность: `isPrivateText` — явные метки `password/пароль/token/секрет/api key/otp/cvv/пин` со значением, `код` + 3–8 цифр, ключи `sk-/ghp_/xoxb-`, приватные ключи, номера карт (13–19 цифр: группами по 4 или по контрольной сумме Луна). Дубликат не плодится: запись поднимается наверх, `copiedAt` обновляется.
- Пределы: число записей, длина одной записи (с пометкой `truncated`), суммарный объём текста — старые вытесняются.
- `list({limit, query})`, `get`, `remove(id)`, `clear()` (работает и с повреждённым файлом), `pause/resume`, `setTtl(ms|null)` (уменьшение сразу чистит старое), `state()` без текстов, `cleanup()`.
- Повреждённый JSON не перезаписывается: операции бросают `файл истории буфера повреждён`, пока владелец не нажмёт «очистить».
- Атомарная запись: временный файл рядом + `rename` поверх, при сбое временный удаляется, прежний файл цел.

### `src/extensions/snippets.js`
- `SnippetStore(filePath, options)` — `{version, items:[{id, trigger, text, createdAt, updatedAt}]}`; внедряются `fs`, `path`, `now`, `maxItems` (100).
- `add`, `update`, `remove`, `list`, `get`, `findByTrigger`, `state`, `clear`; ошибки проверки бросаются **до** записи, файл при отказе не меняется.
- Триггер: 1–40 символов, без управляющих символов; уникальность без учёта регистра/ё/лишних пробелов (`triggerKey`). Текст: 1–4000 символов, не похож на пароль/код/ключ/карту.
- Вставка: `preview(id)` — только чтение; `async insert(id, {confirm, writer})` — без `confirm === true` текст **не отдаётся вообще** и `writer` не вызывается; без `writer` модуль отдаёт текст вызывающему коду, сам ничего не делает; с `writer` (его передаёт `main.js`) вызывает его явно. Ошибка получателя — `writer_failed` без текста вставки.

### `src/extensions/downloads-cleanup.js`
- `analyze(folder, options)` — **только чтение**: обход `readdirSync`, ссылки и junction пропускаются, лимиты `maxFiles` (2000), `maxDepth` (3), `maxCandidates` (200); группировка по возрасту (свежие/до месяца/до полугода/старше), типу (установщики, архивы, картинки, видео, звук, документы, временные, другое) и размеру; кандидаты — старые (`minAgeDays`, по умолчанию 30) и временные/незавершённые файлы; `candidateBytes`, `candidates` (сначала крупные), `scanned`, `issues`. Пустая папка — `{ok:true, status:'empty'}`, не ошибка. Нет папки/это файл — `{ok:false, reason, message}`.
- `remove(candidates, confirm, {folder})` — отдельная функция. Без `confirm === true` (строго булево) не делает ничего. Каждый путь проверяется: относительный, без `..`, без абсолютных/дисковых/UNC путей, внутри папки; `lstat` (ссылка — отказ), `realpath` (junction в середине пути — отказ), сама папка — отказ. Результат всегда перечисляет `removed`, `refused` (защита), `failed` (файла нет, нет прав), `bytesFreed`; `ok === false`, если что-то не удалось. Тихих удач и тихих отказов нет.

## 5. Приватность и безопасность: принятые решения

- История буфера и вставки не пишут в журнал вообще: модули не вызывают `journal` и `console`, в сообщениях об ошибках нет текста. В файле истории секретов быть не может — запись отклоняется до сохранения.
- Эвристики намеренно осторожные: «код 404» тоже не сохранится. Лучше потерять безобидную запись, чем сохранить чужой пароль. Это задокументировано в коде.
- Уборка загрузок: `analyze` не вызывает ни одной пишущей функции; удаление — только `remove` с `confirm === true`; защита от выхода за папку (`..`, абсолютные пути, ссылки, junction) и от удаления самой папки; чужие ошибки не глотаются — попадают в `failed`/`refused`.
- Все операции с файлами атомарные (временный + `rename`); повреждённый файл не перезаписывается молча.

## 6. Контракт IPC для интегратора (`main.js` / `preload.js` / `renderer/*`)

Все обработчики — по образцу существующих: проверка `fromWindow(event)`, синхронные вызовы ядра в `try/catch`, ошибка возвращается `{ok:false, error}` простым русским текстом. Ниже — рекомендуемые каналы; имена можно поменять, важны аргументы и возврат.

### 6.1 Общее
- Папка данных — та же, что у приложения: `process.env.NOX_DATA_DIR || path.join(root, 'data')` (см. `defaultDataDir` в `src/tools/disk.js`).
- Файлы: `path.join(dataDir, 'clipboard-history.json')` и `path.join(dataDir, 'snippets.json')` (в `AGENTS.md` раздел «Данные» их стоит дописать).
- Экземпляры создаются один раз в `main.js`: `const clipboardHistory = new ClipboardHistoryStore(path.join(dataDir, 'clipboard-history.json'));`, `const snippets = new SnippetStore(path.join(dataDir, 'snippets.json'));`.

### 6.2 История буфера
- `clipboard-history:state` → `history.state()` = `{ok, paused, ttlMs, count, chars, maxItems}`. Ошибка чтения повреждённого файла → `{ok:false, error}`.
- `clipboard-history:list`, аргумент `{limit?: number, query?: string}` → `{ok:true, items: history.list(args), state: history.state()}`. `items[] = {id, text, createdAt, copiedAt, truncated}` — новые сверху.
- `clipboard-history:record`, аргумент `{text: string, protected?: boolean}` → результат `history.add(args)` как есть: `{ok:true, saved:true, duplicate?:boolean, item?}` | `{ok:false, saved:false, reason:'empty'|'protected'|'private'|'paused', message}`. Вызывается из наблюдателя буфера; **наши собственные `clipboard_set` не записывать**. Исключений не бросает, обработчик может возвращать напрямую.
- `clipboard-history:remove`, `{id}` → `{ok:true, removed:boolean}`.
- `clipboard-history:clear` → `{ok:true, removed:number}` (кнопка «Очистить»; работает и при повреждённом файле).
- `clipboard-history:pause` / `clipboard-history:resume` → `{ok:true, paused}`; либо один канал `{paused:boolean}`.
- `clipboard-history:ttl`, `{ttlMs: number|null}` → `{ok:true, ttlMs}`; недопустимое значение → `{ok:false, error}`.
- `preload.js`: `clipboardHistory...` методы; `renderer` показывает паузу, срок, кнопки «Удалить запись»/«Очистить».
- Важно: признак `protected` интегратор ставит сам, когда копирование сделал Джарвис или когда известно, что это поле пароля; надёжного системного признака у Electron нет (см. предел в разделе 2).

### 6.3 Быстрые вставки
- `snippets:list` → `{ok:true, items: snippets.list(), state: snippets.state()}`; элемент `{id, trigger, text, createdAt, updatedAt}`.
- `snippets:save`, аргумент `{id?: string, trigger: string, text: string}` → без `id` это `snippets.add`, с `id` — `snippets.update`; успех `{ok:true, item}`; ошибки проверки (`пустой триггер`, `триггер «…» уже занят`, `текст похож на пароль…`) → `{ok:false, error}`; `update` вернул `null` → `{ok:false, error:'такой вставки нет'}`.
- `snippets:remove`, `{id}` → `{ok:true, removed:boolean}`; `snippets:clear` → `{ok:true, removed:number}`.
- `snippets:preview`, `{id}` → `{ok:true, id, trigger, text}` | `{ok:false, reason:'not_found', message}`. Только чтение, ничего не вставляет.
- `snippets:insert`, `{id, confirm: boolean}` → главное правило: `confirm` передаётся **только после явного нажатия владельцем кнопки «Вставить»** и только `true` (строго). `main.js` делает так:
  1) получает `preview`; 2) если `confirm !== true` — вернуть отказ, текст не читать; 3) вызывает `snippets.insert(id, { confirm: true, writer: async (text) => { /* записать в буфер тем же способом, что `clipboard_set` (`Set-Clipboard -Value $env:JARVIS_CLIP`) */ } })`.
  Возврат `{ok:true, inserted:true, id, trigger}` | `{ok:false, reason:'confirm_required'|'not_found'|'writer_failed', message}`. Модуль в буфер сам не пишет.
- `preload.js`: `snippetsPreview`, `snippetsInsert(id, confirm)`; окно обязано спрашивать подтверждение и не вставлять при отмене.

### 6.4 Уборка загрузок
- Папка по умолчанию: `app.getPath('downloads')` (модуль её сам не читает — ему передают явно).
- `downloads:analyze`, аргумент `{}` или `{folder?, minAgeDays?, maxFiles?, maxDepth?}` → `analyze(folder, options)`: `{ok:true, status:'ok'|'empty', folder, message, scanned:{files,dirs,totalBytes,...,truncated}, groups:{byAge,byType,bySize}, candidates[], candidatesTotal, candidatesTruncated, candidateBytes, minAgeDays}` | `{ok:false, reason:'not_found'|'not_directory'|'folder_required', message}`. Экран показывает размер, возраст, причину по каждому кандидату и суммарный объём; ничего не удаляется.
- `downloads:remove`, аргумент `{paths: string[], confirm: true}` (`paths` = `candidates[].path` из анализа; `folder` — та же, что анализировалась) → `remove(paths, confirm, {folder})`: `{ok, removed[], refused[{path,reason}], failed[{path,reason}], bytesFreed, bytesFreedText, message}`. `ok === false`, если был хоть один отказ или ошибка; `refused`/`failed` показывать владельцу. Между анализом и удалением список перепроверяется; `confirm` по умолчанию не ставить и не подменять.
- `preload.js`: `downloadsAnalyze`, `downloadsRemove(paths, confirm)`; удаление — только по отдельной кнопке после показа предпросмотра.

## 7. Остаток и ограничения

1. **Экран и интеграция**: карточки расширений (или раздел «Расширения»), списки истории/вставок, кнопки паузы/очистки/вставки, экран предпросмотра уборки с подтверждением — это `main.js`/`preload.js`/`renderer/*`, зона интегратора. Модули намеренно без DOM и IPC.
2. **`AGENTS.md` и полный прогон**: новые файлы обязан упомянуть `AGENTS.md`, но в этой задаче его менять запрещено. Поэтому полный `node --test` даёт падение `project-map.test.js` (в списке также `src/desks/*` соседней зоны `desks-core`); ещё 4 падения на момент прогона — в `tests/desks.test.js`, зона `desks-core` ещё в работе. Интегратору нужно добавить в таблицу `### Ядро: src/` одну строку (все три файла в ней видны тесту):
   ```
   | `src/extensions/` | `src/extensions/clipboard-history.js` история буфера: пароли, коды и карты не сохраняются, срок хранения, пауза, очистка; `src/extensions/snippets.js` быстрые вставки: уникальные триггеры и текст, вставка только по явному подтверждению; `src/extensions/downloads-cleanup.js` уборка загрузок: анализ и предпросмотр только чтением, удаление только с `confirm` и только внутри папки |
   ```
