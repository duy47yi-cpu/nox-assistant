# Этап 4: чат, живой шар и доступная персонализация — матрица и отчёт

Зона: `renderer/orb.js`, `renderer/orb-variants.js`, `renderer/themes.css`, `renderer/look.js`,
`renderer/accent.js`, `renderer/theme-boot.js`, `renderer/presence.css`, `renderer/home.css`,
`renderer/styles.css`. Общие файлы (`renderer/app.js`, `renderer/index.html`, `main.js`,
`preload.js`, `AGENTS.md`) не менялись — контракты для интегратора в конце.

**Как проверялось.** Настоящее Electron-окно, временный профиль (`NOX_DATA_DIR` в `%TEMP%`),
CDP на порту `:9334`; окно выведено поверх, поэтому `requestAnimationFrame` не throttled
(~90 кадров за 500 мс, шар рисует с потолком 30 кадров/с). Для каждого пункта ниже —
живой замер `getComputedStyle`/`getBoundingClientRect`/ARIA/canvas-хэшей в окне.
Окно `:9333` (рабочее) не закрывалось и не настраивалось, из него только читалось состояние.

Тесты: `node --test` в `apps/jarvis-desktop` — **1646 pass, 0 fail** (36 suites).

## Найденные дефекты (итог)

1. `success`, `verifying`, `cancelled` отсутствовали в шаре; подпись приложения не отдавала их шару. → состояния добавлены в `orb.js` (первый-класс), интегратору осталось передавать их как есть.
2. Нет доступного описания состояния шара; на главной live-регион статуса был `display:none`. → `role="img"` + `aria-label` на обёртке, визуально скрытый (но живой) `#statusText`.
3. Системное «уменьшить движение» игнорировалось (`ignoreSystemMotion`). → шар уважает `prefers-reduced-motion`; при включённых «Анимациях» `main.js` сам ставит `no-preference`, поэтому по умолчанию шар остаётся живым.
4. В `waiting_approval`/`error` цикл кадров продолжал крутиться вхолостую. → цикл останавливается, новое состояние его возвращает.
5. Свой акцент мог дать контраст ниже 4,5:1 на цветных темах. → цвет минимально корректируется по фактическим токенам темы, подпись на плашке выбирается по лучшему контрасту.
6. В узком окне открытая сцена не прятала чат, а её содержимое уходило за верхний край. → исправлено в `presence.css`.
7. Группы «вида» не управлялись стрелками и все были в Tab. → roving tabindex + стрелки/Home/End.
8. Сохранённые настройки вида не проверялись. → `sanitizeLook` (безопасный дефолт на каждое поле).
9. Не было настроек размытия и фона. → добавлены (мгновенно, сохраняются, сбрасываются).

## Что осталось / контракты интегратору

Файлы зоны: `renderer/orb.js`, `renderer/theme-boot.js`, `renderer/look.js`, `renderer/accent.js`,
`renderer/presence.css`; новые тесты `tests/orb-a11y.test.js`, `tests/appearance.test.js`.
`AGENTS.md`, `main.js`, `preload.js`, `renderer/app.js`, `renderer/index.html` не менялись.

1. **`renderer/app.js`, `viewState()`** — «Слушаю» по-прежнему не показывается:
   `return st === 'listening' ? 'idle' : st;`. Диктовка уже есть, шар умеет `listening`.
   Патч: заменить на `return tracker.state;` и в конце `setRecordingUI(on)` (кнопка микрофона)
   добавить `tracker.setListening(on);`. `StatusTracker.setListening` уже написан.
2. **`renderer/app.js`, `syncOrbState()`** — убрать временный маппинг `verifying → acting`,
   `cancelled → idle` (если он есть в ветке): orb.js принимает `verifying`, `cancelled`, `success`
   как есть и рисует их экономно (`verifying` — спокойная дуга, `cancelled` — нейтральный
   серый и остановка, `success` — зелёный `--ok`).
3. **`AGENTS.md`**, строка `renderer/look.js`: дописать «размытие стекла, фон окна».
4. **`DESIGN.md`**: раздел «Вид настольного ассистента» — пункт про шар добавить состояния
   `verifying/success/cancelled` и доступную подпись; «Движение» — уточнить, что шар уважает
   `prefers-reduced-motion`, когда в приложении выключены «Анимации» (main.js тогда не подменяет
   медиа на `no-preference`); «Свой вид» — добавить «Размытие стекла» и «Фон окна».
5. **Позиция шара** (не делалось): «компактно у края во время активного диалога» из глубокой
   спецификации не реализовано — текущая архитектура держит шар на сцене справа (≥1000 px)
   или в отдельной секции (<1000 px). Это изменение `app.js`/`index.html`, отдельная задача.
6. **Проверка плавности «глазами»**: исполнитель не может смотреть PNG (модель без зрения),
   поэтому плавность подтверждена косвенно — частота rAF в окне, разные хэши кадров, отсутствие
   вхолостых кадров в замерших состояниях, тесты orb-life. Визуальную оценку стоит сделать
   владельцу/интегратору по скриншотам `%TEMP%\nox-cdp\evid-*.png`.
7. Временный экземпляр `:9334` поднимался с `NOX_DATA_DIR` в `%TEMP%` и всегда-поверх
   (иначе Chromium throttled скрытое окно). Для правды о настройках он писал только в `%TEMP%`.
