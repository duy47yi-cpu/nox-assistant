# План реализации Nox по видеореференсам

> Для исполнителей: используйте superpowers:executing-plans; выполняйте задачи по порядку и отмечайте доказательства. Не делайте коммиты без просьбы владельца.

**Цель:** реализовать показанные в четырёх видео возможности как работающие сценарии Nox, сохранив уже созданный интерфейс и характер продукта.
**Архитектура:** Windows Electron-приложение владеет действиями на компьютере и локальными данными; сервер отвечает за аккаунты, лимиты и доступ к моделям. Использовать существующие модули, не создавать второе ядро. Каждая возможность доводится от интерфейса до проверенного результата.
**Стек:** Node.js, Electron, существующие HTML/CSS/JS; сервер Node 24+. Сначала читайте `D:/nox-release/AGENTS.md`, `PRODUCT.md`, `DESIGN.md` и соответствующие исходники. Спецификация — данный план и четыре видео из запроса владельца. Видео рекламные, некоторые функции объявлены будущими; незаметные детали не считать доказанными.

## Общие правила

- Не читать `.env` и настоящие `data/`; для проверок задавать временный `NOX_DATA_DIR`. Не устанавливать программы и пакеты без согласия владельца.
- Работа в `D:/nox-release`. Сохранять незакоммиченные изменения других исполнителей; перед правками проверять состояние и договариваться о файлах.
- Существующие ограничения `src/policy/modes.js` обязательны: оплата всегда запрещена; правила разрешений и аварийного стопа не ослаблять. Результат подтверждается проверкой инструмента, а не ответом модели.
- Не копировать чужие логотипы, персонажей, тексты и точные ассеты. Владелец хочет приятный чат и живой шар в центре или у края; ориентироваться на видео и текущий интерфейс.
- Интерфейс: клавиатура, контраст 4,5:1, масштаб Windows 125–150%, отключаемое движение. Модели и провайдеры пользователю показывать как «Быстрая» и «Умная».
- `PRODUCT.md` содержит старое ограничение «голос пока не делаем»; текущий запрос владельца включает диктовку и озвучку из видео и имеет приоритет. Уточнить текущее состояние перед расширением.
- Новые внешние интеграции только через официальные API и собственные ключи владельца. Запуск в production и расходы требуют отдельного распоряжения; этот план не разрешает публикацию.
- После добавления или удаления файлов `src/`/`renderer/` обновить карту `AGENTS.md`. Не выдавать макет или заглушку за работающую функцию.

## Правила проверки

Для каждого этапа: сначала изучить существующий код и тесты; зафиксировать текущий результат и неисправности; внести минимальные изменения; добавить проверку поведения и отказов; выполнить соответствующие тесты; проверить пользовательский путь в настоящем окне, если меняется интерфейс. Записывать путь, данные и результат проверки. Перед заявлением о готовности запустить `node --test` в обеих папках приложений и проверить настоящее окно. Не повторять тесты без причины. Никаких процентов паритета без проверенной матрицы и сопоставимых сценариев.

## Этап 0. Базовая инвентаризация — до параллельной реализации

- [ ] Создать таблицу возможностей: ссылка на видео и время, наблюдаемое поведение, состояние Nox (работает / частично / отсутствует / не проверено), доказательство, зависимость, владелец задачи.
- [ ] Временно настроить отдельный профиль и пройти чат, команду, разрешение, стоп, журнал, память, MCP, голос и аккаунт. Зафиксировать реальные результаты и ошибки, не использовать личные данные.
- [ ] Сверить существующие тесты и карту с кодом: `src/agent/loop.js`, `src/policy/`, `src/agent/effects.js`, `src/commands/`, `src/memory/`, `src/mcp/`, `renderer/`, `apps/nox-server/`.
- [ ] Разбить работу между исполнителями по владению файлами. Изменения общих `main.js`, `preload.js`, `renderer/app.js`, `index.html` и `AGENTS.md` интегрирует один координатор. Останавливать интеграцию при конфликте контрактов.
**Готово:** матрица с доказательствами и список неисправностей; текущий интерфейс и данные сохранены.

## Этап 1. Основной сценарий агента

**Зависит от:** 0. **Код:** `src/agent/`, `src/tools/`, `src/policy/`, `src/agent/effects.js`, `renderer/app.js`.
- [ ] Проследить цепочку «просьба → план → действие → проверка → результат» через существующие интерфейсы. Определить состояния ожидания, выполнения, разрешения, остановки, ошибки и непроверенного результата.
- [ ] Довести индикатор текущего действия и кнопку стоп; остановка должна прекращать следующие действия, включая фоновые, и показывать фактический результат.
- [ ] Показать конкретное действие и его адресата перед разрешением, где оно требуется политикой. Отклонение и закрытие окна не выполняют действие.
- [ ] Реализовать и проверить независимые демонстрации: открыть приложение и выполнить действие; прочитать экран с ошибкой; подготовить сообщение с разрешением по правилам; создать будильник/напоминание там, где доступно. Для почты использовать тестовый стенд.
- [ ] Для каждого действия показывать «подтверждено», «не проверено» или «не удалось», сохраняя запись в истории.
**Готово:** все сценарии проходят в реальном окне, ошибки, отказ и стоп проверены; система не сообщает об успехе без подтверждения.

## Этап 2. Команды и повторение действий

**Зависит от:** 1. **Код:** `src/commands/`, `src/tools/`, `renderer/index.html`, `renderer/app.js`.
- [ ] Проверить создание, редактирование, удаление, включение, поиск, запуск и пробный просмотр команды; добавить недостающие состояния и проверку входных данных.
- [ ] Добавить папки/коллекции, фразы и горячие клавиши, импорт/экспорт с версионированием, предпросмотром и проверкой содержимого.
- [ ] Составить каталог реально реализованных действий и параметров. Не обещать «50 действий», пока они не работают.
- [ ] Запись действий: явный старт/стоп, обзор шагов, редактирование и удаление; предупреждать о ненадёжных координатах. Не записывать секреты. Повтор через существующую политику и проверку результата.
- [ ] Создание из текста: предложить план команды, показать шаги и параметры, дать исправить и сохранить. После успешного задания предлагать сохранить подходящий сценарий; неподдерживаемые действия обозначать.
**Готово:** команда создаётся тремя способами, сохраняется после перезапуска и выполняется с теми же ограничениями, что ручное действие.

## Этап 3. Память, история и данные

**Зависит от:** 0–1. **Код:** `src/memory/`, `src/journal/`, `src/chats/`, `src/missions/`.
- [ ] Проверить автоматическое и явное запоминание, разделение по рабочим пространствам и исключения чувствительных данных.
- [ ] Дать пользователю просматривать, исправлять и удалять записи памяти; отражать результат в дальнейшем диалоге.
- [ ] Сделать историю действий с датой, статусом, причиной ошибки и связанным заданием; поиск и фильтрация. Не записывать секреты в журнал.
- [ ] Проверить заметки, задачи, напоминания и календарное представление: создание, изменение, выполнение, удаление, восстановление после перезапуска и часовой пояс.
**Готово:** факты и задачи сохраняются и удаляются ожидаемо; непроверенный результат не выглядит выполненным.

## Этап 4. Чат, шар и персонализация

**Зависит от:** 0; согласовывать общие файлы с этапом 1. **Код:** `renderer/orb.js`, `orb-variants.js`, `themes.css`, `app.js`, `index.html`.
- [ ] Сохранить текущую компоновку Клода, улучшать по фактическому виду окна и референсам. Чат: читабельные сообщения, вложения, поток ответа, удобный ввод, история, ошибка и повтор.
- [ ] Шар плавно дышит и различимо реагирует на ожидание, слушание, работу, ответ и ошибку; не перекрывает чат. Настроить размер, положение, цвет, интенсивность и отключение движения.
- [ ] Темы: светлая/тёмная, акцент, прозрачность, размытие, фон и выбор шрифта. Показывать изменения сразу, сохранять локально, предусмотреть сброс и читаемость текста.
- [ ] Проверить 125–150% масштабирования, узкое окно, клавиатуру, длинные сообщения и отключённые системные анимации.
**Готово:** настройки переживают перезапуск; шар живой без заметных зависаний, интерфейс удобен при движении и без него.

## Этап 5. Подключения и расширения

**Зависит от:** 0–1. **Код:** `src/mcp/`, `src/tools/`, экран подключений, политика.
- [ ] Проверить добавление, удаление, запуск/остановку и ошибки сервиса MCP. Явно показывать, какие действия он предоставляет и когда требуется разрешение.
- [ ] Сделать каталог проверенных подключений на официальных протоколах; у каждого указать установку, права, состояние и отключение. Не копировать чужие учётные данные или приватные API.
- [ ] Определить единый контракт расширения: версия, разрешения, настройки, жизненный цикл и ошибки. Каждое расширение отключается и не блокирует приложение при сбое.
- [ ] По отдельным задачам реализовать показанные в видео: скриншот с разметкой/OCR/записью; конвертер; история буфера; быстрые вставки; поиск по документам; помощник стримера; уборка загрузок с предварительным просмотром; перерывы.
- [ ] Следующие расширения вести отдельными задачами с техническим исследованием: умный дом, конспекты, субтитры с переводом, чтение вслух, блокировка при уходе, второй компьютер, озвучка уведомлений, питомец. Для каждого описать разрешения, локальное/сетевое выполнение, состояния и критерии до реализации.
**Готово:** каждое опубликованное расширение проходит свой реальный путь и отказы; в каталоге не показываются как готовые нереализованные функции.

## Этап 6. Голос

**Зависит от:** 0–1. **Код:** `src/voice/`, `scripts/tts/`, настройки и поле ввода.
- [ ] Проверить текущую диктовку и синтез: устройства, доступность без сети, задержку и обработку ошибок.
- [ ] Диктовка в поле чата и отдельно — вставка в активное внешнее поле с явным включением. Не перехватывать ввод незаметно.
- [ ] Выбор доступного голоса, громкости и скорости; остановка речи. При потере микрофона или модели показывать причину.
**Готово:** русский голосовой ввод и озвучка проверены на реальном устройстве; отключение возвращает управление пользователю.

## Этап 7. Столы и виджеты

**Зависит от:** 3–4. **Код:** `src/workspaces/`, `renderer/`, реальные источники погоды/валют/музыки.
- [ ] Проверить существующие рабочие пространства и их связь с данными, прежде чем добавлять новый тип «стола».
- [ ] Реализовать вкладки столов: создать, переименовать, переключить, удалить; шаблоны пустой, работа, учёба, игры, медиа и аватар.
- [ ] Сетка: добавить, переместить, изменить размер и удалить виджет; сохранить раскладку, поддержать клавиатуру.
- [ ] Подключать только реальные источники: задачи, календарь, музыка, погода, курсы, системная нагрузка и программы. При недоступности показать состояние, а не выдуманные данные.
**Готово:** несколько столов независимо восстанавливаются после перезапуска; пустые и недоступные виджеты понятны.

## Этап 8. Аккаунт, сервер и подготовка выпуска

**Зависит от:** 0; выпуск зависит от всех обязательных этапов. **Код:** `apps/nox-server/`, `src/account/`, настройки аккаунта.
- [ ] Проверить существующие регистрацию, вход, сессии, выход и лимиты; реализовать недостающие пути, включая восстановление и удаление аккаунта там, где продукт их предлагает.
- [ ] Определить границу локальных и серверных данных, миграции, резервное копирование и проверку доступа между пользователями. Не выводить секреты в клиент и журналы.
- [ ] Если нужна платная подписка: выбрать доступного владельцу официального провайдера, сначала тестовый режим; сервер проверяет подписанные события и обрабатывает повторы. Управление и отмена понятны пользователю. Запрет Джарвису совершать оплату сохраняется.
- [ ] Проверить настройки production, HTTPS, ограничения запросов, наблюдаемость, обновления приложения, сборку Windows, восстановление из резервной копии, политику конфиденциальности и условия.
- [ ] Создать отчёт preflight: результаты тестов, открытые дефекты, статус функций и зависимости от аккаунтов/ключей. Публикация только по отдельному распоряжению владельца.
**Готово:** проверенная сборка и конкретный список блокеров; никакие внешние сервисы не включены без решения владельца.

## Этап 9. Приёмка и передача

- [ ] Пройти сравнительную матрицу по каждому ролику, отмечая источник и результат в Nox; отметить непоказанные конкурентом детали как решения Nox, а не установленный факт.
- [ ] Проверить основной путь в реальном окне: просьба → план → разрешение → выполнение → проверка → история → сохранение команды → повтор после перезапуска.
- [ ] Выполнить тесты обеих частей и проверки сборки; отдельно проверить остановку, ошибку сети, закрытие окна, отказ в разрешении, недоступность интеграции и восстановление.
- [ ] Передать владельцу список готового и непроверенного, команды запуска, известные проблемы и доказательства. Процент паритета считать только из проверенной матрицы; визуальное сравнение делать на одинаковом размере и состоянии.
