# Nox — Система тем (Phase R2)

> Критичная часть. Жалоба «не работает переключение тем» подтверждена: `nox-screen.css` изолирован от `themes.css` [В].

## 1. Диагноз текущей проблемы [В]

| Симптом | Причина | Где |
|---|---|---|
| Переключение темы не меняет экран Nox | `body[data-view="nox"]` задал `--nox-bg:#0F0F10` хардкодом, не читает `[data-theme]` | `nox-screen.css:14–26` |
| Сфера не перекрашивается при смене акцента | `orb-nox.js` палитра хардкод `PALETTE.idle` #4DBCE8, не читает `--accent` | `orb-nox.js: pal()` |
| Светлая тема ломает читаемость | `--nox-text-1:#F1F1F3` на светлом bg — контраст 1.1:1 | — |
| Пользовательский HEX ломает сферу | Нет проверки контраста для сферы, только для текста | `theme-boot.js: readable()` только для текста |

## 2. Принцип [П]: все поверхности — через семантические токены

**Один источник темы:** `themes.css` `[data-theme]` — как сейчас, но экран Nox его читает.

```css
/* themes.css уже имеет 12 тем + system — оставляем. Добавляем алиасы для Nox: */
body[data-view="nox"] {
  --nox-bg: var(--bg);
  --nox-surface-1: var(--surface);
  --nox-surface-2: var(--surface-2);
  --nox-surface-3: var(--surface-3);
  --nox-border: var(--border);
  --nox-border-strong: var(--border-strong, color-mix(in srgb, var(--border) 120%, var(--text)));
  --nox-text-1: var(--text);
  --nox-text-2: var(--text-2);
  --nox-text-3: var(--text-3);
  --nox-accent: var(--accent);
  --nox-accent-soft: var(--accent-soft, color-mix(in srgb, var(--accent) 14%, transparent));
  --nox-ok: var(--ok);
  --nox-warn: var(--warn);
  --nox-err: var(--err);
}
```

**Сфера:** `NoxOrb` принимает `accent` из CSS — `getComputedStyle(document.documentElement).getPropertyValue(''--accent'')` — и пересчитывает палитру `PALETTE` — уже есть `pal()` — только подать цвет [П].

**Результат:** `JarvisTheme.apply(''light'')` меняет `[data-theme]` на `html` — и Nox, и команды, и настройки идут за ней. Без перезагрузки, как сейчас [В].

## 4. Акцентный цвет последовательно [П]

- **Где:** рейка активная, кнопки primary, фокус, сфера, pick-trigger активный, border фокуса капсулы, точка агента — всё `var(--accent)` [В] Luxify «один акцент на всё» [В].
- **Как меняется:** палитра 7 кружков + HEX [В] `accent.js` — уже. При смене — `jarvis:accent` событие — сфера слушает и перекрашивается 280ms linear [П].
- **Контраст акцента:** `readable()` уже сдвигает цвет до 4.5:1 [В] — оставляем. Для сферы — не сдвигаем: сфера — декоративный элемент, не текст — достаточно 3:1 vs bg [П]. Если accent слишком тёмный на dark (например #111111 из lime-темы) — сфера поднимает материал до #3A3A3A [В] уже есть в DESIGN.md.

## 5. Сфера поддерживает акцент без потери состояний [П]

| Состояние сферы | Как различимо при любом акценте |
|---|---|
| idle/listening/thinking/speaking | Оттенки accent (светлее/ярче) — различимы по яркости, не по hue |
| waiting | Полностью warn #F5A524 — hue отличается от любого accent (тест `themes.test.js` проверяет warn отличим [В]) |
| success | ok #3DD68C — зелёный, не пересекается с accent |
| error | err #FF5C5C — красный |

Даже если accent — зелёный #5EE0A0 (как в теме), success ok #3DD68C близок — различаем по анимации (вспышка vs дыхание) [П] — не только цветом.

## 6. Цвета ошибок и предупреждений [П]

- **err:** на dark #FF7F78, на light #B3362D — из `themes.css` [В] — контраст на surface ≥4.5:1 [В].
- **warn:** на dark #FFC24D, на light #8A5800 — янтарь только для «вашей очереди» (waiting_approval) — правило из DESIGN.md [В] — не используем warn для ошибок.
- **Пользовательские темы не ломают читаемость:** `readable()` сдвигает accent, но err/warn — из темы, не из акцента — остаются.

## 7. Пользовательские темы [П]

- Кастом HEX → `readable()` → `data-accent="custom"` → `--user-hue`/`--user-ink` [В] — уже.
- Если кастом слишком светлый на light — сдвигаем к чёрному, подсказка «… поэтому взят #… — темнее» [В] — уже.
- Сфера берёт итоговый `applied` цвет, не `requested` — чтобы не уходить в невидимость.
