# С2: стабилизация диктовки в любое поле Windows (12.11.2026)

Продолжение работы Fable 5.2. Ничего не переписано заново: найдена причина сбоев, исправлена она и проверочный стенд.

## Что было не так

Живой прогон `scripts/field-dictation-qa.js` повторён 3 раза. Воспроизведено 2 разных сбоя «первого шага»:

| Прогон | Что упало | Что показал результат |
|---|---|---|
| 1 (до правок) | прошёл | — |
| 2 (до правок) | `notepadShown: false` | `visible: false`, всё остальное верно: `mic: «Слушаю»`, цель «nox-dictation-qa.txt — Блокнот», текст на месте |
| 3 (до правок) | отказ определения поля | `no_field`: впереди было **чужое окно** («ChatGPT», в фокусе кнопка) — владелец работал за этим компьютером |

### Причина №1 (главная, продукт): окно-подсказка иногда не показывалось

Показ висел на одном событии `ready-to-show`:

```js
dictateWin.once('ready-to-show', () => { if (phase !== 'idle') dictateWin.showInactive(); });
```

У скрытого прозрачного окна (`show: false`, `transparent: true`, `focusable: false`) это событие приходит не всегда.
Итог для владельца: микрофон слушает, текст идёт, а окна на экране нет — нарушено требование С2 «микрофон всегда виден».

### Причина №2 (стенд, не продукт): проверка не удерживала своё предусловие

Замер `CAPTURE_SCRIPT` (тот же скрипт, что в продукте) 25 раз по Блокноту и 25 раз по Chrome: **50 из 50 «ok»**.
Само определение поля стабильно. «Нестабильность» возникала, когда впереди оказывалось чужое окно
(владелец переключался на машине, где идёт прогон) — стенд этого не проверял и записывал это как сбой продукта.

## Что исправлено

**Продукт** (`main.js`, `src/voice/field-dictation.js`):
- `revealDictate()` — одно место показа окна; `hintNeedsShow(состояние, видно)` — чистое решение «пора показать».
- Показ больше не зависит от одного события: `ready-to-show` **и** `did-finish-load`, плюс повтор на каждое
  изменение состояния сеанса. Второе срабатывание ничего не делает (окно уже видно).
- Ничего не ослаблено: сверка окна и поля перед вводом, отказ для поля пароля, ввод без буфера обмена — без изменений.

**Стенд** (`scripts/field-dictation-qa.js`):
- `dictateIn(окно)` — перед нажатием клавиши ставит своё окно вперёд и, если поле не определилось, **спрашивает
  диагностику**: заголовок переднего окна, элемент в фокусе. Отказ засчитывается только когда впереди было наше окно;
  иначе окно возвращается и попытка повторяется (до 3).
- Отказ больше не обрывает прогон: `notepadRefused` / `browserRefused` / `movedRefused` пишутся с диагностикой.
- Окно проверяется на видимость: `notepadVisibleMs` (сколько ждали) и `notepadShown` требуют `visible: true`.
- Своё окно Блокнота называется с pid прогона, при выходе закрываются все окна `nox-dictation-qa-*`
  (у Блокнота Windows 11 окна делят процесс и вкладки — чужой файл в соседней вкладке сбивал чтение поля).
- Уборка при выходе не держит процесс: закрытие окон и браузера уходит отдельным процессом.
- Новое: **проверка переключателя в трее** — галочка «Диктовка в любое поле» снимается и ставится так же,
  как рукой владельца (через собранный шаблон меню), и проверяется по трём внешним признакам: файл настроек,
  регистрация Ctrl+Alt+D, перестроенное меню.

## Регрессионные тесты

`tests/field-dictation.test.js` (+2, всего 12 в файле):
- «окно-подсказка видно весь сеанс»: показывать на capturing/recording/inserting/done/kept/refused, не показывать

## Живые проверки

Прогон `electron scripts/field-dictation-qa.js` (временный профиль и данные в `D:`, не в репозитории):

- после правок: `ok: true` — Блокнот (окно видно, текст виден до вставки, «Вставлено.», проверка чтением поля),
  второй сеанс на готовом окне, Esc-отмена, Chrome (поле, «Вставлено.»), уход фокуса («не вставлено», текст сохранён),
  поле пароля (отказ), переключатель в трее (снят/поставлен), буфер обмена не тронут.
- окно-подсказка появляется за ~0.9–2.1 с (в это время входит запуск PowerShell и чтение поля).
- до правок тот же прогон падал 1 раз из 2 по видимости окна.

## Микрофон

**На этой машине микрофона нет.** Проверено: устройств записи нет (единственный аудио-конец — NVIDIA HDMI),
`SpeechRecognitionEngine.InstalledRecognizers()` пуст, `SetInputToDefaultAudioDevice()` падает с «Распознаватель не установлен».
Поэтому настоящий голосовой ввод проверить нельзя; живой стенд подставляет распознанный текст потоком.
Продукт в этом случае честно пишет «Микрофон не работает» (ветка `no_audio` в `src/voice/dictation.js`).
