## 2. P1 — типографика: изоляция только для Nox

**Причина.** `renderer/theme-boot.js` пишет пользовательские гарнитуры инлайном в `html`: `--font`, `--font-head`, `--font-reply` (значения из `jarvis.look`). Базовый `body { font: … var(--font) }` и сообщения наследовали их, поэтому при «Книжном Sitka»/Georgia весь экран Nox становился серифным. Inter при этом был загружен — это не сбой шрифта.

**Исправление** (`renderer/nox-screen.css`): на `body[data-view="nox"]` объявлены свои токены типографики:
```css
--font: "Inter", "Segoe UI Variable Text", "Segoe UI", system-ui, -apple-system, sans-serif;
--font-head: var(--font);  --font-display: var(--font);  --font-reply: var(--font);
```
Так как объявление стоит на `body`, оно перекрывает унаследованные инлайн-значения `html` только для поддерева Nox. При смене раздела `body[data-view]` правило перестаёт действовать, и классические разделы продолжают следовать настройкам владельца. Файлы шрифтов не менялись, новых зависимостей нет.

**Проверка на реальных значениях профиля.** Значение `jarvis.look` прочитано из реального профиля владельца (`%APPDATA%\jarvis-desktop`, только чтение): `{"ui":"book","head":"georgia","reply":"head","size":"m","round":"m","panel":"m","orb":"l","blur":"m","bg":"theme","glow":true,"winAlpha":"0","winRadius":"0"}`. Это же значение записано в изолированный временный профиль (реальный профиль не изменялся), после чего измерены `font-family`:

| Элемент Nox | До | После |
|---|---|---|
| `body` | `Sitka Text, Sitka Small, Georgia, … serif` | `Inter, "Segoe UI Variable Text", "Segoe UI", system-ui, …` |
| Заголовок «История» | Sitka (serif) | Inter |
| Строка истории | Sitka | Inter |
| Текст сообщения `.md` | Sitka | Inter |
| Поле ввода / подсказка | Sitka | Inter |
| Пилюля модели | Sitka | Inter |

- `document.fonts.check('14px Inter','Привет') === true` — кириллица в Inter доступна.
- Классические «Настройки» в том же профиле остались `Sitka Text… serif`.
- После смены пользовательской гарнитуры на «Системный Windows / Cambria» Nox остался Inter, а классические «Настройки» стали `"Segoe UI Variable Text"…` — то есть изоляция работает в обе стороны.

## 3. P1 — вариант `nox` сферы: проверка без переделки

Код `renderer/orb-nox.js` в этом этапе **не менялся** (mtime 09.11 23:26, как и до задачи): «не заменяй случайной новой 3D-моделью». Проверено на живом окне и в изолированном профиле:

- **Равномерность точек.** 1400 точек оболочки строятся по Fibonacci-сфере (`y = 1 − 2i/(N−1)`, золотой угол), 200 точек ядра — `r ∝ cbrt(rand)`; на скриншотах 864×520 и 1200×720 нет сгустков на полюсах, плотность визуально равномерная.
- **Выразительность ядра.** Ядро `0.42R` видно как объёмное свечение с более светлым центром; не плоский круг, не «Юпитер». Остаётся авторским вариантом Nox (по `orb-spec.md`), а не копией проволоки.
- **Свечение.** Ореол сдержанный (сила 0.14 в idle, до 0.22 в thinking), край холста не засвечивается, «квадрата» от клиппинга нет (радиальный clamp проверялся в этапе 1; в текущих снимках артефактов нет).
- **Плавность.** В видимом окне 1200×720, DPR 1: rAF 180.2 FPS (541 кадр/3 с), внутренний `getStats().fps = 180`; варианты wire и nox — одинаково ровно, без рывков.
- **Resize.** Тест в настоящем окне: 864×520 → 960×640 → 1200×720. Холст остаётся квадратным (240×240 / 240×240 / 332×332 CSS, attr = CSS×DPR), сфера сохраняет пропорцию и центр, горизонтального переполнения нет. Отдельно модуль слушает `ResizeObserver` и `window.resize`; интеграция дополнительно вызывает `resize()`.

Снимки: [after-1200x720-nox.png](fixes-2026-11-10/after-1200x720-nox.png), [after-864x520-wire.png](fixes-2026-11-10/after-864x520-wire.png), [verify-fps-nox-1.png](fixes-2026-11-10/verify-fps-nox-1.png).

## 4. P2 — геометрия композера и левой группы

**Композер.** Высота уменьшена до 76 px, на узком окне поле сжато по краям. Замеры DOM в настоящем окне (DPR 1):

| Окно | До (QA/этап 1) | После |
|---|---|---|
| 864×520 | 296×82 | **284×76** |
| 960×640 | 296×82 | **380×76** |
| 1200×720 | 476×82 | **484×76** |

Высота 76 достигнута за счёт `padding: 7px 12px` у капсулы (8 px на узком) и снятия лишнего `margin-top` у выбора модели; многострочный ввод и доступность кнопок сохранены. Ширина 284 при 864×520 достигается inset 22 px внутри панели (панель чата в нашей сетке шире кадра — 330 против ~309, поэтому «натуральная» ширина по краю дала бы 296; выбран вариант, совпадающий с числом QA).

**Переход рейка↔история.** В референсе рейка и история читаются как одна панель. Теперь так же: у `.app` в Nox нет зазора между рейкой и `.main`; рейка получила фон панели, левые скругления и общую границу; у истории убраны левая граница и левые скругления (`border-radius: 0 16px 16px 0`). В пустом состоянии (история скрыта) та же левая панель продолжается центральной панелью чата. Геометрия подтверждает стык: `history.x == rail.x + rail.w` (61 = 9+52 при 1200; 55 = 9+46 при 864). Остальные панели и функции рейки не менялись.

## 5. P2 — копирование ответа

Добавлена настоящая кнопка под каждым ответом ассистента (`.nox-copy`), не декоративная:

- Копирует текст именно своего ответа (`innerText` блока `.md`, пустые строки нормализуются, концевые пробелы обрезаются).
- Основной путь — `navigator.clipboard.writeText`, резервный — скрытая `textarea` + `document.execCommand('copy')`; результата два состояния: «Скопировано» (зелёная галочка, 1.4 с) или «Не удалось скопировать» (красный тон).
- Доступность: `button`, `aria-label`/`title` «Скопировать ответ» → «Скопировано» → возврат; видимый `:focus-visible` (2 px #2E9AC1), hover меняет цвет/фон/рамку, размер 26×22 px, не влияет на вёрстку соседних сообщений.
- Пока ответ печатается (`.md.is-streaming`), кнопка скрыта — копировать нечего.
- Кнопка добавляется наблюдателем ленты к уже отрисованным ответам; в классическом экране не показывается (стили ограничены `.view-nox`, у базового `.nox-copy` `display:none`).
- Попутно исправлен побочный эффект: добавление кнопки увеличивало высоту ответа на ~30 px уже после автопрокрутки, из-за чего лента могла остаться на 30–90 px выше низа. Теперь при добавлении кнопок лента переприжимается к низу, если пользователь был внизу; если он читает выше — позиция не меняется.

Проверка в настоящем окне (`verify-report.json`, check `copy-button`): клик по кнопке последнего ответа → `clipboard.readText()` в главном процессе = «Ответ локального тестового сервера.» (35/35 символов, точное совпадение), `aria-label` «Скопировать ответ» → «Скопировано» → возврат, `:focus-visible` 2 px `rgb(46,154,193)`, hover-стиль реально меняется, сдвиг `offsetTop` предыдущих сообщений = 0, 31/31 кнопок на месте после проверки.

Снимки: [compare-copy-button-before-after.png](fixes-2026-11-10/compare-copy-button-before-after.png), [verify-copy-1.png](fixes-2026-11-10/verify-copy-1.png).

## 9. Что проверено, а что осталось неподтверждённым

**Проверено:** изоляция шрифтов на точных значениях из реального профиля; возврат к пользовательской гарнитуре в классических разделах; всё выше по геометрии/копированию/сферам/функциям/FPS; тесты.

**Не подтверждено / ограничения:**
1. **Реальный профиль живьём не перезапускался.** Владелец держит открытым экземпляр со старой сборкой; останавливать его мы не стали. Вместо этого точные значения `jarvis.look` из реального профиля воспроизведены в изолированном профиле, и проверка выполнена там. Окончательное визуальное подтверждение — после обычного перезапуска приложения владельцем.
2. **Hover проверялся программно** (смена вычисленных стилей при наведении и фокусе), а не физической мышью; `:focus-visible` подтверждён реальным фокусом.
3. **FPS** снят при DPR 1 и работающем простаивающем экземпляре владельца; на HiDPI/при фоновой нагрузке числа могут быть ниже (в этапе 1 wire на DPR 1.73 показывал ~50 FPS в программном композитинге).
4. **Вариант `wire`** намеренно не перерабатывался (по заданию — отдельная задача); его фактурное расхождение с видео из QA остаётся.
5. Тестовый стенд не заменяет приёмку на реальном ключе модели: отмена проверена на локальном потоке, а не на реальном провайдере.
