# Phase 3.4 — критерии приёмки

Этап считается принятым, когда выполнены все его критерии и нет открытых дефектов из раздела «Риски» этого этапа в `security-checklist.md`. Колонка «Проверка» ссылается на сценарии из `test-scenarios.md`.

---

## Общие критерии (обязательны для каждого этапа)

| ID | Критерий | Проверка |
|---|---|---|
| AC-G.1 | `node --test` в `apps/jarvis-desktop` проходит; число тестов не меньше базовой линии этапа 0 | Команда, отчёт |
| AC-G.2 | `node --test` в `apps/nox-server` проходит | Команда, отчёт |
| AC-G.3 | Окно проверено в настоящем окне 1200×720 и 864×520 | Снимки во временной папке |
| AC-G.4 | В текстах окна нет названий моделей и поставщиков | Поиск по строкам (V-07) |
| AC-G.5 | Журнал и файл разговора не содержат текст ввода `SECRET-PROBE-42` | S-01 |
| AC-G.6 | Нет коммитов и `push` без просьбы владельца | `git log` до и после |
| AC-G.7 | `.env` и `data/` не открывались | Отчёт о проверке |
| AC-G.8 | Нет новых списков запретов для «Полного доступа» и нет Windows Hello | Просмотр изменений |
| AC-G.9 | Отчёт о готовности: что проверено настоящим окном, что тестами, что не проверено | Текст отчёта |

## Этап 1. Журнал: один источник статуса

| ID | Критерий | Проверка |
|---|---|---|
| AC-1.1 | Для каждой записи статус в «последних» (`journal:recent`) и в поиске (`journal:search`) одинаковый | T-N01, T-N11, J-14 |
| AC-1.2 | Рискованное действие без проверки (`status:'unverified'`) показано как «Не проверено», не «Выполнено» | J-06 |
| AC-1.3 | Шаг, прерванный стопом, имеет статус «Остановлено», не «Ошибки» | J-16, T-N03 |
| AC-1.4 | Аварийный стоп (`decision:'stop'`) имеет статус «Остановлено»; `decision:'resume'` не отображается как «Выполнено» | J-17, T-N04 |
| AC-1.5 | Старые записи без `status` получают статус по прежним полям; миграции файла нет | Файл из тестового профиля со старыми записями |
| AC-1.6 | Поле `status` цикла не теряется в ответах ядра | T-N02 |

## Этап 3. Ход агента: честная остановка

| ID | Критерий | Проверка |
|---|---|---|
| AC-3.1 | «Остановлено» появляется в окне только после события `done` с `outcome:'stopped'` | A-10, V-04 |
| AC-3.2 | После `done` ни одна строка хода не остаётся в «выполняется»; незавершённые закрыты статусом «остановлено» | A-10, T-N06 |
| AC-3.3 | Результат инструмента, пришедший после остановки, отображён `late_result` и записан в журнал с `afterStop:true` | A-12, T-N05 |
| AC-3.4 | Стоп во время подтверждения: карточка закрыта, инструмент не запущен | A-11, S-15 |
| AC-3.5 | Стоп не запускает следующий шаг и следующий вызов модели | A-11 |
| AC-3.6 | Инструменты из списка R-15 либо прерываются по сигналу, либо явно помечены как «ждём завершения» в окне | Проверка по списку |
| AC-3.7 | Тон «Остановлено» в экране Nox отличается от «Готово» | V-05 |

## Этап 4. Подтверждения

| ID | Критерий | Проверка |
|---|---|---|
| AC-4.1 | Решение относится к одному действию: `id` уникален (`runId` + `callId`); дубликат закрывает старый запрос с событием | S-11, T-N08 |
| AC-4.2 | Сбой или таймаут ответа на подтверждение не убирает карточку; кнопки снова активны через 8 с | S-08, S-12, T-N09 |
| AC-4.3 | После перезагрузки окна карточка восстанавливается из `approval:pending`; повторного запуска инструмента нет | S-05 |
| AC-4.4 | Текст ввода в карточке и в строке хода маскирован; полный текст открывается только по действию владельца и не сохраняется | S-03, S-04, T-N07 |
| AC-4.5 | Предпросмотр файла в карточке ограничен по длине | S-03 |
| AC-4.6 | Ожидавший шаг не выполняется после перезапуска процесса; журнал не содержит «выполнено» для него | S-07 |
| AC-4.7 | Голосовой ответ решает только текущую карточку; «да» не даёт «на сессию» | S-20 |
