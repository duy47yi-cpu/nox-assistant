# Phase 3.4 — чек-лист безопасности и устойчивости

Статус: анализ по коду, без запуска. Серьёзность: **высокая** — нарушает правило «не показывать успех без подтверждения» или ведёт к действию без разрешения; **средняя** — расхождение состояния или потеря данных; **низкая** — неудобство или косметика.

Ограничения владельца, которые действуют на эту работу:
- «Полный доступ» не сужается отдельным списком запретов команд (решение 08.11.2026). Фаза 3.4 не добавляет такой список.
- Windows Hello не добавлять без отдельной просьбы.
- Пользователь не видит названий моделей и поставщиков; проверять тексты окна.
- Оплата запрещена всегда.
- `.env` и `data/` не читать и не показывать.

## 2. Что уже сделано правильно (не трогать без причины)

- Маскировка при записи в журнал: `Journal.append`, `maskSecrets`, `TYPED_TEXT_TOOLS`, `BARE_TOKEN`.
- Решение `decide` до запуска инструмента; секрет в исходящем всегда спрашивается; оплата — `deny`.
- Отмена хода отклоняет ожидающие подтверждения (`_askApproval` → `respond('reject')`).
- Аварийный стоп отменяет все подтверждения (`approvals.cancelAll`, `main.js` ~771).
- Два клика «Разрешить» не дают двойного вызова (`A.busy`).
- Ответ на закрытое подтверждение — «запрос уже неактуален», без повторного запуска.
- Чужие окна не получают журнал и подтверждения (`fromWindow`).
- Уведомление о подтверждении не содержит аргументов.
- Одноразовые инструменты (send, delete, pay) не получают «на сессию» (`isOneShot`).

## 3. Чек-лист перед приёмкой этапов

- [ ] Текст ввода (`ui_type`, `clipboard_set`, `browser_type`) не попадает в журнал, файл разговора, `turns.jsonl`, DOM строки хода и карточку (кроме решения владельца, R-04).
- [ ] Предпросмотр файла в подтверждении ограничен по длине и маскирован (R-07).
- [ ] Статус в окне и в поиске совпадает для каждой записи (R-01).
- [ ] «Остановлено» не записывается как «Выполнено» или «Ошибка» (R-02, R-18).
- [ ] После `done` с остановкой ни одна строка хода не остаётся в состоянии «выполняется» (R-03).
- [ ] «Повторить» не запускает выполненные шаги (R-08).
- [ ] Кнопки подтверждения возвращаются через таймаут при сбое IPC (R-11, R-12).
- [ ] `id` подтверждения уникален; дубликат не отклоняет чужой запрос молча (R-13).
- [ ] Перезагрузка окна не даёт повторного запуска и не оставляет карточку без ответа (R-09).
- [ ] Перезапуск приложения не выполняет ожидавший шаг (R-10).
- [ ] Журнал виден только текущему пространству или есть явный переключатель (R-21).
- [ ] Журнал читается с учётом ротации и не блокирует окно (R-20, R-22).
- [ ] Сбой записи журнала виден владельцу (R-19).
- [ ] Тексты окна не содержат названий моделей и поставщиков (R-29).
- [ ] В тестах нет реального отправления, оплаты и удаления вне временной папки.
- [ ] `.env` и `data/` не открывались.
- [ ] Нет новых списков запретов для «Полного доступа» (ограничение владельца).
- [ ] Новые файлы в `src/` или `renderer/` добавлены в карту `AGENTS.md` (тест `project-map.test.js` падает без строки).
