# Phase 3.1 — раздел «Команды» в дизайн-системе Nox

Дата: 2026-11-10. Основание: `docs/reconstruction/phase2/design/*` (design-system, navigation-layout,
commands-ui, components, motion, implementation-handoff), макеты `previews/01-commands.png`,
`previews/02-editor.png`. Сделано поверх готового чата Phase 1.1 без переписывания приложения.

что при сохранении, без запуска. После «Проверить»/«Запустить сейчас» панель показывает результат.

## Сверка с макетами

Совпадает: каркас (рейка 52 самостоятельной панелью, одна панель раздела, скругления 16), шапка
72 px с «Команды» 24/600 и «+ Новая», вкладки 40 px с акцентной активной, поиск 40 px, справа
«Записать/Импорт/Экспорт», список строками-карточками 64+ с шевроном, чипами и мета, «Запустить»
и переключатель 32×20 справа; панель паков 288 px `surface-1` с карточками и ссылкой «Что внутри»;
редактор: шапка с «←» и крошкой, основная карточка `surface-1` с полями и шагами, правая карточка
«Результат проверки» с точками и подсказкой, нижняя панель 64 px; диалог выбора действия 640×520
с категориями 158 px и списком; палитра и типографика — токены `design-system.md`.

Отличия (осознанные): в шапке добавлены кнопки окна «свернуть/развернуть/закрыть» — окно без
системной рамки, в макете их нет; у карточек паков показана строка подсказки от ядра («Нужно: …»),
которой нет в макете, но она предусмотрена `commands-ui.md` §1.4; кнопки нижней панели редактора
идут в порядке «Проверить · Запустить сейчас · Отмена · Сохранить» (как в `commands-ui.md` §2.1),
в макете порядок нарисован иначе; в строке списка происхождение показано словом в мета-строке
(«запись», «из описания»), а не отдельной плашкой.

## Ограничения и что не подтверждено

- **«Создать команду по описанию» из редактора не реализовано**: отдельного IPC нет, `command_build`
  доступен только агенту в чате. Кнопку-обманку не добавляли.
- **Диалог выбора действия** берёт список из `tools:catalog`, а сервер отдаёт только
  `EDITOR_STEP_TOOLS` (`app_open`, `ui_keys`, `wait`, `speak`, `volume_set`), поэтому категорий
  ровно шесть, а действий пять; мышь/почта/опасные инструменты не предлагаются. Категории — локальные
  подписи, а не данные сервера.
- **Перетаскивание шагов мышью** не делалось: только «выше/ниже» (как и раньше).
- **Импорт/экспорт** проверены по существующей логике: предпросмотр импорта снимался с подменённым
  системным диалогом, сам системный выбор файла и сохранение в файл автоматически не проверялись.
- **Запись** фиксирует только `tool_start` инструментов агента, а не все физические клики; текст и
  секреты не пишутся — это ограничение существующего механизма, в интерфейсе сказано честно.
- **Порядок кнопок и подсказки паков** отличаются от макета (см. выше); кнопки окна добавлены
  вынужденно.
- **Найдена и исправлена чужая ошибка**: в `renderer/app.js` `chatTool()` сравнивал тип события с
  необъявленной переменной `tool_result` вместо строки `'tool_result'` (было и в git HEAD). Из-за
  этого каждый `tool_start`/`tool_result` давал `ReferenceError` в консоли и ломал строку действий
  хода в чате. Исправлено одной строкой; QA после исправления — 15/15, консоль чистая.
- Светлая тема, сфера и «Полный доступ» в этом этапе не трогались.
