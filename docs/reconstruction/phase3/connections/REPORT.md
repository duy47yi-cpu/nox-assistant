# Phase 3.2 — раздел «Подключения» (MCP) в дизайн-системе Nox

Дата: 2026-11-10. Основание: `docs/reconstruction/phase2/design/*` (design-system, navigation-layout,
connections-ui, components, motion, implementation-handoff), макет
`previews/03-connections.png`. Сделано поверх готовых чата, «Команд» и MCP-ядра; контракты IPC,
формат `mcpServers`, снапшоты инструментов и пользовательские данные не менялись.

## Что реализовано

1. **Главный экран**: заголовок «Подключения», кнопка «Добавить сервис», поиск по безопасным
   метаданным (имя, адрес/команда, состояние, действия, протокол/сервер — без ключей и заголовков),
   чипы-фильтры по состояниям, список карточек, панель «Популярные», пустое состояние, «ничего не
   найдено», баннер ошибки чтения состояния с повтором.
2. **Семь состояний** (`statusOf`): `connected`, `connecting`, `disabled`, `idle`, `legacy`,
   `error`, `drift`. У каждого — своя пилюля (цвет + текст + точка/иконка, различимо без цвета),
   строка состояния, набор действий и честный текст причины. «Подключён» показывается только при
   реальном `status: 'connected'` от `McpManager`; сохранённый но не подключившийся — «Ошибка» с
   причиной; изменившийся набор действий — «Изменения инструментов» с блокировкой действий до
   подтверждения.
3. **Работающие действия** (только существующий мост): добавление (`mcp:add`), детали и
   возможности (`mcp:state`), включение/выключение (`mcp:toggle`), удаление с подтверждением имени
   (`mcp:remove`), подтверждение изменений инструментов (`mcp:approve`), повтор подключения для
   ошибки (тот же `mcp:add`/`mcp:toggle`), автопроверка состояния каждые 3 с, пока раздел открыт.
   Кнопка «Повторить» у ошибки вызывает существующий `mcpToggle(name, false)`.
4. **Каталог популярных**: 7 проверенных записей без ключей из `src/mcp/catalog.js` (Файлы,
   Puppeteer, Память, PostgreSQL, Playwright, Context7, Рассуждения) — «+ Добавить» ставит сервис
   одним действием. Ещё 3 записи макета (Slack, GitHub, Google Диск) честно показаны как
   «Не настроено» с причиной (нужен ключ/вход, не проверено) и не притворяются рабочими.
   Категории — локальные: Все / Файлы / Разработка / Прочее. Ключи в окно не подставляются,
   секретов в данных нет.
5. **Диалоги**: добавление сервиса (560×480), детали (480×520), подтверждение удаления,
   подтверждение изменений инструментов, ошибка подключения. Все — нативные `<dialog>`:
   Escape, focus trap, возврат фокуса на вызвавший элемент (включая случай, когда карточка
   перерисовалась опросом), блокировка кнопок на время запроса, ошибки показываются внутри
   диалога и не теряются.

Подтверждение набора действий сервиса (`mcpApprove`) — отдельное решение и **не** смешивается с
разрешением агенту выполнять системные действия (`approval:respond`): это прямо сказано в тексте
деталей и диалога изменений.

## К чему подключён интерфейс

| Действие | Мост (`preload.js`) | Канал (`main.js`) | Бэкенд |
|---|---|---|---|
| Список/состояния | `mcpState` | `mcp:state` | `McpManager.state()` (`src/mcp/client.js`) |
| Добавить / повторить | `mcpAdd` | `mcp:add` | `McpManager.add()` |
| Вкл/выкл | `mcpToggle` | `mcp:toggle` | `McpManager.toggle()` |
| Детали/возможности | `mcpState` | `mcp:state` | `tools`, `serverInfo`, `capabilities`, `drift` |
| Подтвердить изменения | `mcpApprove` | `mcp:approve` | `McpManager.approve()` + `src/mcp/drift.js` |
| Удалить | `mcpRemove` | `mcp:remove` | `McpManager.remove()` |
| Каталог популярных | статическая часть `src/mcp/catalog.js` в окне | — | сверяется тестом `mcp-catalog` |

Новых IPC-каналов и методов моста не добавлялось. Формат `settings.json` (`mcpServers`,
`mcpToolSnapshots`) не менялся; состояние после добавления/выключения/удаления сохраняется ядром
тем же `saveSettings`, что и раньше (покрыто тестом `mcp-manager`: «настройка сохранена, как её
увидит следующий запуск»).

4. поиск сужает список и популярные, сброс возвращает; поиск не теряется при смене фильтра;
5. все фильтры и счётчики;
6. детали открываются кликом по карточке, показывают адрес/команду, действия, разрешения,
   переключатель; Escape закрывает и возвращает фокус;

11. ошибка: «Повторить» остаётся ошибкой и показывает честную причину в диалоге (фокус

14. пустое состояние: `#mcpEmpty` виден, 0 карточек, популярные на месте;
15. чат и «Команды» целы после посещения «Подключений», возврат без ошибок;

## Сверка с макетом

Совпадает: каркас Nox (рейка 52, одна панель раздела, скругления 16), шапка 72 с «Подключения»
24/600 и акцентной «+ Добавить сервис», поиск 360×40, чипы-фильтры 32, карточки 100+ с иконкой
32×32, именем 14/600, пилюлей состояния 20 px, моно-адресом и строкой состояния, контекстной
кнопкой справа («Детали» / «Включить» / «Повторить» / «Подтвердить изменения»), панель
«Популярные» 348 px `surface-1` с категориями и строками «имя + описание + Добавить», палитра и
типографика из `design-system.md`.

Отличия (осознанные, зафиксированы здесь):

- в шапке есть кнопки окна «свернуть/развернуть/закрыть» — окно без системной рамки, в макете их
  нет;
- у пилюль-фильтров показаны счётчики (в макете только подписи) — это функциональная подсказка;
- три записи макета (Slack, GitHub, Google Диск) честно помечены «Не настроено» с причиной, а не
  кнопкой «Добавить»: у них нужны ключи/вход или запуск не проверен;
- у карточек дополнительно строка «Действия (N): …» (требование `connections-ui.md` §1.2) — в
  макете её нет, из-за неё карточка чуть выше;
- список данных в макете — шесть примеров; в приложении показываются реально настроенные сервисы
  (в фикстурах — четыре состояния).

## Ограничения и что не подтверждено

- **`idle` и `legacy`** реализованы и покрыты юнит-тестом, но нынешний `McpManager` не создаёт их
  в живом приложении: все включённые сервисы стартуют при запуске, а `legacy` — только ответ
  старой сборки. Не выдаём их за проверенные в окне.
- **`connecting`** виден кратко во время реального подключения (снят в раннем прогоне), но в
  финальном QA его окно не поймано из-за быстрого локального сервера.
- **Перезапуск приложения** в UI-проверке не автоматизирован: сохранение настроек подтверждено
  тестом `mcp-manager` (save → load следующего запуска) и тем, что все изменения идут через
  существующий `saveSettings`. После перезапуска экран читает `mcp:state` при входе и в опросе.
- **Пакеты npx/uvx** одним кликом не ставились и в проверке не нажимались: в подсказке диалога
  честно сказано, что пакет может скачаться при первом запуске, и это действие владельца.
- **Копирование адреса** в деталях использует `navigator.clipboard` с запасным путём; успех
  показывается тостом, но автоматически в QA не проверялся.
- Реальные ключи, внешние API и чужие сервисы не использовались: фикстуры — локальный stdio
  MCP-сервер на `node`, несуществующая команда (ENOENT), выключенный http-адрес и снапшот
  инструментов для drift.
- При подтверждении изменений (mcpApprove) показывается diff, но полный список действий сервиса
  до/после не раскрывается отдельным экраном — только чипы добавленных/удалённых/изменённых.
