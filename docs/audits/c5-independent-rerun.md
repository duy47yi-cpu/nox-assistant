## 2. Метод и что именно проверено

1. Полное чтение кода обеих папок (мост, протокол, клиент, контроллер, popup, извлекатель, manifest, тесты).
2. Штатные наборы: `node --test` в каждой папке.
3. Независимые негативные тесты, написанные с нуля, без правок исходников:
   - реальный мост (`createBridge`) и реальный клиент расширения по настоящему WebSocket;
   - поддельный («враждебный») мост для атак на клиент;
   - контроллер расширения с управляемыми `chrome.tabs`/`chrome.scripting` (детерминированные гонки);
   - E2E «контроллер + настоящий мост»;
   - проверки гейта сообщений `background.mjs`, извлекателя, UTF-8-фаззинг, статический поиск утечек.
4. Живой стенд Chromium: service worker MV3 → loopback WebSocket, проверка заголовка `Origin`
   и CSP формы, как в аудируемом manifest.
5. Разбор оставшихся теоретических окон (тайминги, доверительная модель).

Никакие внешние сайты, чужие аккаунты и настоящие пользовательские данные не использовались.

### 2.3. Живая проверка Chrome-платформы

Стенд: `docs/audits/c5-rerun/chrome-probe/` (отдельное probe-расширение; не копия
аудируемого). Chromium **155.0.8059.84**, headless, изолированный профиль.

Результат (`probe-result.json`):

```json
{ "url": "/nox",
  "origin": "chrome-extension://ehnphehgpddhdlaapflmmpkglmmkcflc",
  "host": "127.0.0.1:28417",
  "userAgent": "... HeadlessChrome/155.0.0.0 ..." }
```

Подтверждено: service worker MV3 шлёт **`Origin: chrome-extension://<id>`** на loopback
WebSocket, а CSP формы аудируемого manifest (`script-src 'self'; object-src 'self';
connect-src ws://127.0.0.1:*`) соединение не блокирует. Это ключевое допущение проверки
Origin в мосте.

Чего живой стенд **не** проверяет: полный путь аудируемого расширения с `activeTab`
(нужен настоящий клик по action, которого в headless нет). Поэтому пункты `CHROME-QA.md`
остаются заявлением автора; независимо перепроверены только платформенные допущения.
Стабильный Chrome 157 в этом окружении игнорирует `--load-extension` (в т.ч. с
`--enable-unsafe-extension-debugging`), поэтому стенд запущен на установленном Chromium 155.
Chrome для Testing из `%TEMP%\nox-cft-repair-...` (156.0.8078.4) запустить не удалось:
sandbox не может прочитать исполняемый файл в Temp (`0x5`), network service падает. Это
не дефект C5, но означает, что живой прогон 156 в этом аудите не воспроизведён.

**F1 (P3, устойчивость). Поздний `read_result` после таймаута моста убивает всю сессию.**
Воспроизведение: BR-11B — после `readPage({timeoutMs: 40})` отправить корректно подписанный
результат; мост отвечает `unexpected read_result` и завершает соединение.
Ожидаемое: игнорировать результат для истёкшего `requestId` (короткий grace) либо
закрывать только чтение, не сессию. Утечки нет; страдает доступность.

**F2 (P3, согласованность протокола). `busy`-ответ клиента несовместим с фатальной
обработкой «неожиданного» `read_result` в мосте.** Воспроизведение: CL-08 — при двух
pipelined `read_request` клиент исполняет один и отправляет `{ok:false,error:'busy'}` с
requestId второго; мост счёл бы такой кадр неожиданным и закрыл сессию.
Сегодня недостижимо: мост сам сериализует чтения. Если в мосте появится очередь —
сессия будет рваться. Ожидаемое: либо мост не шлёт второй запрос, либо клиент не
отвечает на него отдельным кадром.

**F3 (P3, устойчивость). `seq` расходуется до фактической отправки в обе стороны.**
`bridge.readPage` увеличивает `serverSeq` до `ws.send`; `client.sendSigned` увеличивает
`sequence` до сборки/отправки. Сбой отправки/сборки оставляет дыру в последовательности,
и следующее сообщение будет отклонено как нарушение порядка. Утечки нет, возможна
потеря сессии в редком сбое сокета.

**F4 (P2, сопровождение с security-составляющей). Критичный клиент существует в двух
копиях.** `apps/nox-browser-bridge/client.mjs` и `apps/nox-browser-extension/client.mjs`
идентичны побайтово; `fitReadResult` в клиенте дублирует `messages.fitReadResultFrame`;
константы лимитов продублированы в `protocol.js`/`messages.mjs`/`client.mjs`/`page.mjs`
(в `page.mjs` намеренно 49 280/600). Правка в одной копии не доедет до второй; теста
равенства нет. Ожидаемое: один источник либо тест, сверяющий хэши и константы.

**F5 (P3, согласие). Открытый grant переживает закрытие popup.** После клика и закрытия
popup мост может однократно прочитать ту же вкладку в течение 60 с; в интерфейсе
обратный отсчёт после закрытия не виден. Это соответствует тексту уведомления
(«однократно, не дольше 60 секунд»), но является остатком согласия. Условие: не делать
автоповторов и фоновых чтений; сохранить одноразовость и текст уведомления.

**F6 (P3, модель угроз). Нет проверки пользовательского жеста на сообщении `read-current`.**
Скомпрометированный popup может выдать grant без клика. Границы: только активная
вкладка на момент вызова, одноразово, ≤ 60 с, в памяти, без сохранения и без новых
сайтов; у скомпрометированного popup уже есть доступ к API расширения. Постоянных
разрешений это не создаёт (CT-11).

**F7 (P2, доверительная модель). HMAC аутентифицирует расширение/сессию, а не страницу.**
Скомпрометированное расширение или профиль браузера может прислать любой текст и любой
канонический origin. Проверка `Origin` в мосте защищает от веб-страниц/DNS rebinding, но
не является аутентификацией клиента: локальный не-браузерный клиент может подставить
заголовок. Подлинность даёт только pairing-секрет. Следствие для интеграции: текст
страницы — недоверенные данные, действия по нему — через политику подтверждений.

**F8 (P3, гонка). Отзыв после последней синхронной проверки, но до отправки подписанного
кадра, не отменяет доставку.** Окно — доли миллисекунды–единицы мс (между финальной
проверкой и подписью/отправкой); текст уже извлечён по действующему grant, новых данных
не появляется. Ожидаемое: принять как остаток либо проверять отзыв внутри сборки кадра
(потребует связать контроллер с отправкой).

**F9 (P3, ресурсы). Нет таймаута на `executeScript`/`tabs.*` в контроллере.**
Зависший вызов Chrome держит запись в `inFlight` до разрешения промиса (отзыв помечает
её aborted, власть не сохраняется); память ограничена одним объектом. Ожидаемое: при
желании — таймаут и принудительное завершение операции.

**F10 (P3, упаковка). Тесты расширения берут `ws` из `apps/nox-browser-bridge/node_modules`.**
Без соседней папки тесты не запустятся. Не безопасность, но условие воспроизводимости.

Дополнительно (не дефект, ловушка для будущих правок): две функции `allowedOrigin`
различаются намеренно — `protocol.js` требует канонический origin без пути, `page.mjs`
принимает любой http(s)-URL и возвращает origin. Перепутанное использование сломает
либо функциональность, либо проверку. Это стоит зафиксировать тестом/комментарием.

Чего **не** найдено: обхода согласия, повторного использования grant, чтения чужой
вкладки, подмены результата без ключа, replay после разрыва, обхода направления/порядка,
постоянных разрешений из popup, записи текста в файлы/логи/хранилище.

## 6. Условия безопасной интеграции (гейт GO)

1. Feature flag остаётся **выключенным по умолчанию**; включение — только для контролируемого
   теста. Наблюдаемое `browserBridgeEnabled === true` это выполняет.
2. Секреты pairing и текст страницы — только в main process и только в памяти: без логов,
   `settings.json`, журналов, телеметрии и отчётов. Ошибки логировать без текста.
3. Текст вкладки маркируется как недоверенный (`source: browser_extension`, `untrusted: true`);
   `taint` для исходящих действий и «рук» сохраняется; C5 не включается в режиме, где
   модельные действия выполняются без подтверждения. Это прямой ответ на P0.10.
4. Никаких автоповторов `readPage` после `permission_required`/`busy`; одно чтение — один
   клик; уважать `read_in_progress`; ошибки показывать честно.
5. Один клиент/сессия. Если появится возможность нескольких — всегда передавать `sessionId`
   (иначе `readPage()` без id отказывает при > 1 сессии).
6. На выходе приложения мост закрывается (`close()`), при отзыве — без «тихого» реконнекта;
   после `revoke` требуется новый pairing (проверено).
7. Сохранить привязку к `127.0.0.1`, точному Origin расширения и запрет `0.0.0.0`.
8. Не расширять manifest: без `host_permissions`, `content_scripts`, `externally_connectable`,
   `web_accessible_resources`; клики/ввод на странице остаются отключены.
9. Устранить F4 (единый клиент или тест равенства) до включения флага; зафиксировать хэш
   загружаемого расширения и ID в конфиге моста.
10. Повторить **живой** прогон настоящего расширения в Chrome ≥ 116 на целевом билде
    (пункты `CHROME-QA.md`) перед включением флага. В этом аудите независимо подтверждён
    только платформенный минимум: Origin и CSP (§2.3).

## 7. GO / NO-GO

- **C5 как компонент — GO** для контролируемой интеграции за выключенным флагом при
  выполнении условий §6. Ни одного P0-обхода не найдено; 48/48 независимых атак и 30/30
  штатных тестов проходят; живой стенд подтверждает ключевое Chrome-допущение.
- **Включение по умолчанию и заявление «C5 готов к выпуску» — NO-GO** до: (а) живого
  прогона настоящего расширения на целевом Chrome, (б) устранения F4, (в) подтверждения
  условий §6 в финальном слое интеграции Terra.
- Готовность всего Nox к выпуску — **вне области** этого отчёта.
