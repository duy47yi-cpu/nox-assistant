# 05. Память и голос

## Память: что есть

Хранилище — один файл `memory.json` (`src/memory/store.js`, 610 строк). Проверено только юнит-тестами.

| Требование | Есть | Как |
|---|---|---|
| Память разговора | да | `history`, хвост `maxContext`, старые ходы сжимаются |
| Память между запусками | да | `memory.json`, `conversation.json` |
| Предпочтения | да | виды `profile`, `agreement`; закреплённые виды идут в каждый ход (`profileNote`) |
| Проекты | да | пространства со своей памятью и целями (`src/workspaces/`) |
| История задач | да | журнал, дела, задачи, миссии |
| Поиск по прошлым разговорам | **нет** | `src/chats/book.js` поиска не имеет |
| Поиск по смыслу | **нет** | совпадение слов и основ слов (`stem`), счёт = число совпавших слов |
| Контекст текущего действия | частично | `memoryContext(store, text)` подбирает записи по словам сообщения |
| Противоречия | да | `conflicts`, `supersedes` |
| Устаревание | частично | срок `until`; проверки «факт давно не подтверждался» нет |
| Удаление по просьбе | да | `forget`, правка и удаление в Настройках, очистка пространства |
| Прозрачность | да | список в Настройках с флагами |
| Согласие на чувствительное | частично | `looksSensitive` помечает, чувствительное не идёт в контекст без запроса; явного вопроса «запомнить это?» нет |
| Секреты | да | `looksSecret`: пароли и ключи не сохраняются |
| Факт или догадка | частично | авто-память берёт только слова владельца (`src/memory/learn.js`); у записи есть `source` и `quote`. Метки «уверенность» нет |

Вывод: память управляемая и осторожная — это редкость и это правильно. Слабое место одно: **находит только то, что названо теми же словами**. «Мой начальник» не найдёт запись «руководитель — Ирина». И разговоры прошлого месяца не ищутся вообще.

## Память: чем искать

| Способ | Плюсы | Минусы | Цена | Для Nox |
|---|---|---|---|---|
| JSON-файл (сейчас) | Просто, прозрачно, легко удалить | Читается целиком; поиск по словам | 0 | Достаточно до нескольких тысяч записей |
| SQLite | Надёжная запись, выборки, не читать всё в память | Перенос данных | 0. У Node 24 есть встроенный `node:sqlite`; сервер Nox уже на SQLite | Для журнала и истории чатов — да |
| Полнотекстовый поиск (FTS5 в SQLite) | Быстрый поиск по словам на любых объёмах, ранжирование | Синонимы и перефразировки не ловит; русские словоформы — нужна своя обработка основ (она уже написана: `stem`) | 0 | **Первый шаг.** Закрывает поиск по прошлым разговорам |
| Векторы (embeddings) | Ловит смысл и перефразировки | Нужна модель: облачная (платно, текст уходит наружу) или локальная (сотни мегабайт, установка) | Облако: цены UNKNOWN, не сверялись. Локально: 0 за запрос | Второй шаг, только если замер покажет, что слова не справляются |
| Векторная база отдельно | Миллионы записей | Лишняя программа | — | Не нужна: у одного человека десятки тысяч записей, хватит перебора или расширения SQLite |
| Гибрид: слова + векторы | Лучшее качество | Два индекса | как у векторов | Цель, если второй шаг оправдается |

Рекомендация по порядку:

1. Перенести историю чатов и журнал в SQLite с FTS5. Добавить инструмент `chats_search` и поиск в окне. Память оставить в JSON, пока записей мало.
2. Собрать 50 пар «вопрос → запись, которую надо найти» из обезличенных примеров. Измерить, сколько находит поиск по словам.
3. Если находит меньше 80 % — добавить локальную модель векторов как необязательную загрузку. Облачные векторы для личной памяти не брать по умолчанию: это вынос личных данных.

## Память: что добавить по управлению

- Дата последнего подтверждения у факта. Давно не подтверждавшиеся факты подаются модели с пометкой «возможно, устарело».
- Явный вопрос перед сохранением чувствительного (здоровье, деньги, адреса, чужие люди).
- Поле «сказал владелец» / «вывод помощника». Выводы никогда не закрепляются.
- Кнопка «что ты обо мне знаешь» — выгрузка всего одним файлом; «забудь всё» уже есть по пространству.
- Для несовершеннолетних: авто-память выключена по умолчанию.

## Голос: целевая схема

```
микрофон → определение речи (локально) → потоковое распознавание → модель (поток текста)
         → резка на фразы → потоковая озвучка → динамик
              ↑ перебивание: речь владельца глушит динамик и останавливает ход
```

1. **Свой захват звука** в окне (стандартный доступ к микрофону в Electron), определение речи локально. Тогда заработает и написанный `agc.js`.
2. **Потоковое распознавание**: слова приходят, пока человек говорит; конец фразы определяется по паузе.
3. **Ответ начинается раньше конца генерации**: текст модели режется по предложениям, первое предложение уходит в озвучку сразу. Событие `text` с `delta` уже идёт из `Agent` — нужна только резка и очередь.
4. **Короткая реплика до действий**: «Сейчас посмотрю» звучит сразу, пока идут инструменты. Локально, без модели.
5. **Перебивание**: при речи владельца — остановить звук за десятки миллисекунд, ход остановить через `Agent.stop()`.
6. **При плохой сети**: распознавание и озвучка откатываются на локальные; ответ показывается текстом.

## Голос и рискованные действия

Разговор и разрешение — разные каналы.

- Голосом можно: спросить, попросить действие, остановить («стоп», «хватит») — остановка всегда безопасна.
- Голосом нельзя: одобрить запрос подтверждения. Одно «да» не привязано к карточке, может быть сказано не Nox, может прийти из динамика или видео. Zero-mercy уже ловил это как R2-02.
- Если когда-нибудь понадобится: только для обратимых действий, только фразой с названием действия, которое Nox произнёс («да, переименовать отчёт»), только пока карточка на экране, и никогда для отправки, удаления, установки и оплаты.

## Низкий взрослый голос с металлом

Это свойство голоса, а не движка. Варианты: подобрать готовый голос у поставщика; сделать свой голос у поставщика с правом на продажу; лёгкая обработка звука локально (понижение тона, фильтр) поверх любого голоса. `src/voice/personas.js` сейчас меняет только темп и громкость. Скорость и естественность важнее тембра: сначала поток, потом тембр.
