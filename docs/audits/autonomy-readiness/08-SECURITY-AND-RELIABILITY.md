## Решение владельца, которое мешает продаже

В `AGENTS.md` записано решение от 08.11.2026: «Полный доступ» не сужается списком катастрофических команд, владелец решает сам. Для личной сборки владельца это его право. **Для продукта по подписке так нельзя**: покупатель не автор кода, среди покупателей будут подростки, а команды оболочки (`shell_run`) в «Полном доступе» не ограничены списком запретов.

Предложение, не меняющее решение владельца для его сборки: флаг сборки владельца уже есть (`src/config/build.js`, `OWNER_BUILD`). В сборке для продажи «Полный доступ» в нынешнем виде недоступен; верхний уровень там — L3 из таблицы ниже.

## Уровни автономии

| Уровень | Что можно | Подтверждения | Чему соответствует сейчас |
|---|---|---|---|
| L0. Советы | Только текст | — | чат без инструментов |
| L1. Чтение | Файлы разрешённых папок, сцена окна, веб-поиск | Снимок экрана и новые папки — по разрешению | инструменты T0 |
| L2. Обратимые действия в границах | Запись в рабочей папке с копиями, открыть программу, раскладка окон, свой браузер | Ничего вне границ | режим «спрашивать» + T1 внутри рабочей папки |
| L3. Многошаговые задачи | Руки в разрешённых программах, документы, почта-черновики | Каждое внешнее, необратимое, удаление, установка, ввод после чужого текста | ближе всего «Полный доступ» с заражением контекста, но без нынешних «без вопроса по прямой просьбе» для оболочки |
| L4. Фон в согласованных рамках | Долгое поручение или задача с мандатом: список инструментов, папок, срок, бюджет | Задаются заранее мандатом; всё вне мандата — отказ, не вопрос | `long.js`, `tasks/mandate.js` |

По умолчанию для нового пользователя — L1, переход выше — явным действием с объяснением. Неограниченного режима в продаваемой сборке нет. Обход UAC и защит Windows не делается и не предлагается: окно повышения прав — всегда стоп и человек.

## Несовершеннолетние и личные данные

Сейчас в коде нет ничего про возраст. Нужно до продажи:

- Возраст при регистрации; для младше порога — потолок L2, авто-память выключена, почта и исходящие выключены.
- Понятный список: что уходит на сервер (текст запросов к модели, снимки экрана, звук при облачном голосе) и что остаётся на компьютере. Сервер Nox текст переписки не хранит (`store.js`) — это стоит сказать прямо. Провайдеры моделей текст получают; их условия хранения — UNKNOWN, проверить по договорам.
- Снимок экрана может содержать чужие личные данные. По умолчанию — только по просьбе (уже так: `screenAuto`), с вырезкой вместо полного экрана.
- Журнал и память — выгрузка и удаление одной кнопкой.
