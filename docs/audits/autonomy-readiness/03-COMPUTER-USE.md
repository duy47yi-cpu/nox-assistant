# 03. Руки и глаза: управление компьютером

## Что есть и что показала проба

Проба: своё окно WinForms с кнопкой, выключенной кнопкой, надписью и полем ввода; инструменты Nox вызывались напрямую, без модели. Результаты в `evidence/probe-result.json`.

| Шаг | Результат | Время |
|---|---|---|
| Найти окно в списке (`ui_windows`) | найдено | 1,2 с после запуска окна |
| Прочитать элементы (`ui_elements`) | 3 из 4: поле ввода не попало; кнопки с ролью `Pane` | 101 мс первый раз, 36 мс повторно |
| Снимок сцены (`desktop_observe`) | 3 элемента с id, 196 символов текста для модели | 101 мс |
| Выключенная кнопка | `enabled: false`, нажатие отклонено | — |
| Нажать кнопку по id (`desktop_click`) | нажатие дошло, надпись сменилась на «State clicked» | 1986 мс |
| Проверка нажатия | «не проверено: видимых изменений нет», хотя сцена показала «появилось 1, исчезло 1» | входит в 1986 мс |
| Ввод в поле по имени (`ui_type`) | «поля ввода нет» | 46 мс |
| Нажатие по устаревшему id | отклонено, просит новый снимок | — |

Оговорка: это одно синтетическое окно. Пропущенное поле и роль `Pane` могут быть особенностью WinForms. Но три вывода от этого не зависят:

1. Чтение дёшево и быстро, нажатие медленно. Две секунды на одно нажатие — это 40 секунд чистых рук на задачу из 20 шагов, без учёта модели.
2. Проверка отделена от действия и не врёт в сторону успеха. Зато врёт в сторону сомнения.
3. Покрытие элементов неполное, а запасного пути «не нашёл в дереве → посмотри картинкой именно это место» нет.

## Что мешает Nox управлять Windows самому

| № | Пробел | Где | Статус |
|---|---|---|---|
| H1 | Проверка нажатия не подтверждает явный успех | `verify` у `desktop_click` в `src/tools/observe.js`: ответ вложенной `clickVerdict` считается окончательным, дельта сцены игнорируется | ПОДТВЕРЖДЕНО пробой |
| H2 | Нажатие занимает около 2 с | `ui_click` + пауза + повторное чтение окна | ПОДТВЕРЖДЕНО пробой, причина по частям не измерена |
| H3 | Часть элементов не видна | `ui_elements`, отбор и роли | ПОДТВЕРЖДЕНО на одном окне |
| H4 | Снимок и координаты снимка только для основного монитора | `PrimaryScreen` в `screen.js`, `mouse.js` | по коду |
| H5 | Разный масштаб мониторов не учтён | `SetProcessDPIAware` (общий на систему) | по коду |
| H6 | Нет перетаскивания, выделения мышью, удержания клавиш | инструмента нет | по коду |
| H7 | Нет ожидания «пока появится X» как части действия | есть отдельные `ui_wait`, `wait_for`; после нажатия фиксированные 150 мс | по коду |
| H8 | Нет обработки неожиданного диалога | дельта сцены покажет, но правила «всплыло окно → прочитай его первым» нет | по коду |
| H9 | Браузер пользователя недоступен по разметке | `browser_*` работает только в своём скрытом Chromium | по коду |
| H10 | Экран шлётся модели целиком | `screen_look`: 1280 px, весь основной монитор | по коду |
| H11 | Неизвестно, видит ли быстрая модель картинки | `wireMessage` шлёт `image_url`; поддержка у выбранной модели не проверялась | UNKNOWN |
| H12 | Окна почты, мессенджеров и банков для рук закрыты всегда | `HARD_WINDOW` в `src/policy/modes.js` | намеренно; это ограничивает сценарии, но снимать запрет без отдельного решения нельзя |

## Сравнение способов управления

| Способ | Сильное | Слабое | Цена и скорость | Когда брать |
|---|---|---|---|---|
| A. UI Automation | Имена, роли, состояние, точные координаты. Нажатие через Invoke не зависит от масштаба и перекрытия | Электрон-приложения, игры, холсты, свои элементы часто пусты или неполны | Десятки миллисекунд, сотни символов текста | Первый выбор для обычных программ Windows |
| B. Разметка страницы (DOM) | Полная структура, устойчивые цели, чтение текста без картинки | Нужен свой браузер или расширение в браузере пользователя | Миллисекунды, текст | Всё, что в вебе |
| C. Снимок + модель со зрением | Работает везде, где есть пиксели | Дорого, медленно, координаты ошибаются, чужой текст на картинке | Каждый снимок — оплата картинки и секунды ожидания. Для сравнения: у Claude набор «компьютер» добавляет около 4,5 тыс. входных токенов к запросу, а каждый снимок считается как картинка (документация Anthropic, см. `07`) | Только когда A и B не дали цель |
| D. Мышь по координатам | Последнее средство для безымянного | Не знает, что под курсором; ломается от масштаба, сдвига окна, перекрытия | Быстро, но без проверки | Только с координатами от A или после C, с проверкой перед нажатием |
| E. Гибрид | Берёт дешёвое первым, дорогое по необходимости | Нужна ясная лестница перехода | В среднем близко к A | **Рекомендуется** |

У Nox уже есть A, B (свой браузер), D и зачаток C. Не хватает лестницы между ними и дешёвого C.

## Целевая схема

```
Наблюдать → Понять → Спланировать → Действовать → Проверить → Продолжить
```

**Наблюдать.** Лестница источников, от дешёвого к дорогому:
1. Сцена окна из UI Automation (уже есть: `desktop_observe`).
2. Разметка страницы, если цель в браузере.
3. Распознавание текста Windows на вырезанной области (`image_read_text` уже есть): бесплатно и локально.
4. Вырезанная область картинкой в модель со зрением.
5. Полный снимок — только по просьбе владельца или когда пункты 1–4 пусты.

**Понять.** Модель получает текст сцены и дельту с прошлого шага, а не всё заново. `diffScene` это уже делает. Добавить: стабильные элементы (меню, панель инструментов) держать в кэше по подписи окна (`sceneSignature`) и не слать повторно.

**Спланировать.** Модель называет цель шага и **ожидаемое изменение**: «после нажатия появится окно „Сохранить как“». Сейчас ожидание нигде не записывается, поэтому проверять нечем, кроме общей дельты.

**Действовать.** Порядок: Invoke по имени → Invoke по id → мышь по центру координат из UI Automation → мышь по координатам с картинки. Перед мышью уже есть проверки `outside`, `occluded`, `no_focus`. Добавить: сверку, что под точкой тот же элемент, что был в наблюдении.

**Проверить.** Три уровня, от дешёвого:
1. Состояние самого элемента (переключатель включился, текст поля равен введённому).
2. Дельта сцены совпала с ожиданием шага.
3. Вырезанная область картинкой — только если 1 и 2 молчат, а действие важное.

Правило для H1: если вложенная проверка ответила «не знаю», а дельта сцены непустая и совпала с ожиданием шага — это подтверждение. Сейчас дельта в этом случае отбрасывается.

**Продолжить.** После двух неподтверждённых шагов подряд (`_unverifiedStreak` уже есть) — обязательное наблюдение. После трёх без изменений (`STALL_LIMIT` уже есть) — стоп и вопрос владельцу.

## Масштаб, мониторы, размеры окон

| Вопрос | Сейчас | Что сделать |
|---|---|---|
| Масштаб не 100 % | `SetProcessDPIAware`: координаты в настоящих пикселях основного монитора | Перейти на учёт масштаба по каждому монитору (Per-Monitor V2) в процессе PowerShell |
| Второй монитор | Снимок и пересчёт координат снимка — только основной | Снимать монитор, на котором окно-цель (`Screen.FromHandle` уже используется в `windows.js`), хранить смещение и масштаб вместе со снимком |
| Окно сдвинулось после наблюдения | `desktop_click` перечитывает окно перед нажатием | Оставить. Для мыши: координаты хранить относительно окна, а не экрана |
| Окно изменило размер | id элемента привязан к роли, имени и номеру вхождения, не к координатам | Оставить |
| Устаревшее наблюдение | отказ по id | Добавить срок жизни сцены: старше N секунд — перечитать до действия |

Проверять всё это надо на настоящем железе: 100 %, 125 %, 150 %, два монитора с разным масштабом. В аудите это NOT TESTED.

## Как удешевить глаза

1. Картинка — последняя ступень, а не первая. В `screen_agent` сейчас наоборот: «начни со снимка экрана», и свежий снимок после каждого действия.
2. Вырезка вместо полного экрана: окно-цель или прямоугольник вокруг элемента.
3. Распознавание текста Windows до модели: бесплатно, локально.
4. Не слать сцену, если подпись не изменилась.
5. Картинки из прошлых ходов уже заменяются текстом (`wireMessage`) — оставить.
6. Отдельная дешёвая модель со зрением только для шага «найди на картинке». Нужен замер; цены и качество — UNKNOWN.

## Критерии готовности рук

Набор из 30 сценариев на настоящих программах (Блокнот, Проводник, Параметры, Калькулятор, окно сохранения файла, браузер), каждый по 10 прогонов:

- доля доведённых до конца без человека — не ниже 90 %;
- ложных «сделано» — ноль;
- доля настоящих успехов, помеченных «не проверено», — не выше 10 %;
- медиана одного действия с проверкой — не больше 700 мс;
- доля шагов, где понадобилась картинка, — измерить и держать ниже 15 %.

Сейчас ни одно из этих чисел не измерено.
