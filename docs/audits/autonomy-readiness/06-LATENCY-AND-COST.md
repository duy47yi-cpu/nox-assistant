## Путь запроса и где теряется время

```
ввод → справка из памяти → запрос к модели → инструмент → проверка → ответ → голос
```

| Звено | Что там | Оценка вклада | Основание |
|---|---|---|---|
| Ввод голосом | распознавание целиком после фразы | неизвестно | не работает на этой машине |
| Справка из памяти | чтение `memory.json`, подбор по словам | мало | код; не измерено |
| Запрос к модели | системный промпт ~25,7 тыс. символов + описания ~100 инструментов + история | **главное** | 2 с на короткий вопрос — почти всё здесь |
| Шаги модели | каждый шаг — новый запрос | **главное на задачах** | 7 вызовов = 37 с: около 5 с на шаг |
| Инструмент чтения | десятки миллисекунд | мало | ЗАМЕР |
| Инструмент действия | около 2 с на нажатие | заметно на задачах с руками | ЗАМЕР |
| Проверка | внутри действия | входит выше | — |
| Снимок экрана | PowerShell + сжатие + отправка картинки | секунды; не измерено | код |
| Ответ в окне | поток по `delta` | мало | код |
| Голос | после конца хода, целиком | прибавляет всё время хода к первому звуку | код |

Два главных вывода:

1. **Время уходит в модель, а не в Nox.** Собственный цикл занимает миллисекунды. Ускорять надо число вызовов модели, размер запроса и выбор модели.
2. **Второе место — руки.** Две секунды на нажатие — это свои, не модельные секунды.

## Что уже сделано для скорости

- Поток ответа (`stream`, `onDelta`), замер первого текста (`firstTextMs`).
- Прогрев соединения и кэша (`Agent.warm()`).
- Чтения выполняются одновременно (`Promise.all` для T0).
- Старые ходы сжимаются, картинки прошлых ходов заменяются текстом.
- Время и справка добавляются к сообщению пользователя, чтобы не сбивать кэш системного промпта.
- Короткие фразы без модели (`src/shortcuts/offline.js`, музыка, курс, команды).
- Кэш точных ответов (`src/cost/response-cache.js`).
- Живой PowerShell (`ps-host.js`).

Это хорошая база. Ниже — чего не хватает.

## Маршрут по сложности

Предлагаемая лестница. Решает код до вызова модели, модель может попросить ступень выше.

| Ступень | Когда | Чем | Цена |
|---|---|---|---|
| 0 | Точная команда, громкость, таймер, курс, погода, сохранённый сценарий | без модели (уже есть) | 0 |
| 1 | Вопрос, разговор, одно действие | быстрая, размышления выключены | ~$0,0001–0,0004 |
| 2 | Поиск, файлы, несколько шагов | быстрая, размышления средние | ~$0,002–0,005 |
| 3 | План длинной задачи, сверка итога, тупик после двух неудач | умная или быстрая с высоким уровнем | в разы дороже, редко |
| Зрение | Только когда структурных данных нет | модель со зрением, вырезка | UNKNOWN |

Правило подъёма: две неудачи подряд или план длиннее 8 шагов. Правило спуска: следующий ход начинается со ступени 1.

Важно: замер из `plan.md` показал, что «умная» модель справилась с длинным поручением хуже быстрой. Поэтому ступень 3 сначала проверить на наборе задач из `04`, а не включать по названию.

## Тарифная схема

Сохранить нынешний принцип: лимит в себестоимости, пользователю — проценты. Добавить:

- Три счётчика внутри лимита: текст, зрение, голос. Пользователь видит один процент, сервер знает, что его съело.
- Пробный и Pro: зрение и облачный голос ограничены жёстче или локальные; Max: полные.
- Фоновая работа — отдельная часть лимита, чтобы долгое поручение не съело разговоры.
- Цена Pro: пересчитать после замеров зрения и голоса. С нынешним запасом $2,04 добавлять облачный голос в Pro за $10 нельзя.
