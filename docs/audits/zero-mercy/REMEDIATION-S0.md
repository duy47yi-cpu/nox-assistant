# NOX Zero Mercy — remediation S0

Дата: 11.11.2026

## Изменения

- `apps/jarvis-desktop/src/agent/loop.js`, `src/screen/agent.js`: каждое разрешение получает отдельный случайный ID. Событие несёт также ID экземпляра агента, текущего хода и исходного вызова модели. Ответ и отмена используют только ID разрешения; ID вызова сохранён для строки действия в чате.
- `apps/jarvis-desktop/renderer/app.js`: строка действия связывается с запросом по `callId`, а кнопки ответа передают отдельный ID разрешения. Диалог автоматически открывается и закрывается при решении/отмене; его можно открыть повторно. Escape отклоняет запрос. Ошибка IPC или ожидание дольше 5 секунд не удаляет запрос, кнопки снова включаются, текст не выдаёт ошибку связи за подтверждение.
- `apps/jarvis-desktop/main.js`: принятое ядром решение отдельно сообщается окну вместе с ID запроса и метаданными связи. Это синхронизирует очередь, даже если ответ IPC не дошёл до renderer.
- Регрессионные тесты обновлены в `tests/approvals.test.js`, `tests/loop.test.js`, `tests/screen-agent.test.js`.
- Живой фиктивный прогон: `docs/audits/zero-mercy/evidence/approval-s0-live.js`; результаты и снимки находятся в `evidence/electron-temp/journal-window-s0-approval-verified/` и `journal-window-s0-ipc-final/`.

В `main.js` и `renderer/app.js` уже были незакоммиченные изменения других работ. Они сохранены; правки этой фазы ограничены обработкой подтверждений.

## Повторные проверки

- **Совпавшие ID и гонка:** два агента с одинаковым исходным ID получают разные разрешения; нажатие при поступлении второго запроса разрешает только действие, показанное в открытом диалоге. Поздний повтор старого ID отвергается. В живом окне выполнено только фиктивное действие `audit-visible-race-first`.
- **Одновременные запросы:** живой прогон показал два отдельных запроса в очереди и сохранение первого открытого действия.
- **Открытие, отказ и повторное открытие:** диалог открывается автоматически; Escape отклоняет запрос, закрывает диалог и не запускает действие. После ошибки IPC диалог повторно открывается для того же запроса.
- **Таймаут и отмена:** автоотмена очищает запрос, закрывает диалог и не вызывает эффект; существующие тесты также проверяют таймауты, `cancel`, `cancelPrefix`, отказ и запрет повторного ответа.
- **IPC:** синтетическая ошибка до ответа оставила запрос в очереди. Синтетическое зависание сняло блокировку кнопок по таймауту интерфейса; по автоотмене ядра запрос закрылся. Следующий фиктивный запрос разрешился, выполнен только он.
- **Режимы разрешений:** прежние тесты политики и агента прошли, включая отказ, `once`, `session`, авто-режим, полный доступ, опасные экранные действия и безусловный запрет оплаты.
- `node --test` в `apps/jarvis-desktop`: **2141 пройден, 0 ошибок**.
- `node --test` в `apps/nox-server`: **31 пройден, 0 ошибок**. Серверные файлы не менялись.

Все живые действия были in-memory фикстурами в отдельных профилях. Реальные системные команды, внешние запросы и платные вызовы не выполнялись.

## Остаточный риск

Прогон имитировал отказ и зависание обработчика IPC, но не аварийное завершение Electron или ОС одновременно с принятым решением. При обычном принятии решение теперь подтверждается отдельным событием из ядра; восстановление после физического обрыва процесса этим прогоном не проверялось.

По проверенным сценариям ZM-001, ZM-013 и ZM-018 повторно не воспроизвелись.
