## Новые регрессии исправления S0

- **N2 (P1):** после решения по A кнопки следующего запроса заблокированы, работает только Escape. Причина — новое `approval_closed` из `main.js:3546` приходит раньше ответа IPC при `A.busy` (`renderer/app.js:1696, 1735`).
- **N3 (P2):** карточка-призрак после самоотмены агента. `tool_result` больше не снимает карточку из-за разделения ID (`app.js:3101`).
- **N4 (P2):** ложное «Не удалось передать решение… Запрос остался в ожидании», когда действие выполнено.
- **N8 (P3, по коду):** строка в чате связана по `callId` и может показывать одно действие, а «Решить» открывает другое.

## Блокирует ли выпуск

Да. **N1 — подтверждение уходит действию, которого владелец не видел.** Последствие такое же, как у ZM-001, условие тоже: два источника запросов и нажатие в узком окне. Самый вероятный момент — нажатие на последней секунде 30-секундного отсчёта. Пока N1 не закрыт, гарантию «подтверждаю то, что вижу» дать нельзя.
