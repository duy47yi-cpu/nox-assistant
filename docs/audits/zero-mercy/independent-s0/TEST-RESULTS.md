## Свои тесты ядра

`evidence/core/zm-core.test.js`, запуск из корня репозитория: `node --test docs/audits/zero-mercy/independent-s0/evidence/core/`. Итог: **15 из 15**, журнал `evidence/core/zm-core.test.log`. Тесты написаны с нуля и не повторяют тесты Codex: те проверяют два агента и форму события, а эти проверяют поведение при атаках.

| Тест | Что доказывает |
|---|---|
| два агента, одинаковый `callId` | разные `approvalId` и `agentId`; B не заменяет A в брокере; одобрение A выполняет только A |
| ответ по `callId` | старый протокол отклоняется ядром |
| обратный порядок доставки | каждое решение достаётся своему действию |
| три агента | выполнены ровно одобренные |
| повторный ответ | второй `once` и `session` → `false`, эффект один |
| отказ и новый запрос с тем же `callId` | старый ID не одобряет новый запрос |
| истёкший запрос | `false` + причина; эффекта нет |
| стоп во время ожидания | поздний ответ отклонён; эффекта нет |
| стоп в одном такте после `once` | шлюз после одобрения не пускает |
| подделка `session` для `*_send` | выполнено один раз, «на сессию» не запомнено, второй вызов снова спрашивает |
| неизвестные решения | `TypeError`, запрос не снят |
| агент экрана: опасный шаг | разные `approvalId` при одинаковом `callId`, `allowSession:false` |
| `RESIDUAL` | брокер молча заменяет запрос с тем же явным ID (N9) |
| `REGRESSION` | самоотмена агента не шлёт `approval_closed`; `tool_result.id` ≠ `approvalId` (N3) |
| `INFO` | `broker.list()` — порядок регистрации (для голоса, N7) |

Тесты с пометками `RESIDUAL` и `REGRESSION` проходят, потому что фиксируют текущее поведение. Это доказательство дефекта, а не исправления.
