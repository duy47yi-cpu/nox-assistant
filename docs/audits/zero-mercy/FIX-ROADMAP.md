# План исправлений

Исходники в рамках аудита не менялись. Очерёдность ниже учитывает вероятность и цену ошибки, а не объём работ.

## 0. Блокер выпуска — ZM-001 (P0)

- Ввести уникальный ID ожидания, связанный как минимум с агентом, ходом и вызовом инструмента; сырой ID модели оставить только как атрибут диагностики.
- Не заменять старое pending-ожидание при коллизии. Завершать конкретный запрос отказом и показывать владельцу ошибку совпавшего ID.
- При ответе сверять ID, агента, имя инструмента, аргументы/их безопасный отпечаток и текущий статус ожидания.
- Сделать одну очередь источником истины для брокера и диалога; дубликат не должен молча менять действие за видимой карточкой.

**Выпускной критерий:** тест с двумя параллельными фиктивными агентами и одинаковым исходным ID никогда не выполняет второй вызов после согласия на первый; экран показывает обе операции отдельно или блокирует обе.

В этой же серии исправить ZM-013. Привязать счётчик к существующей кнопке «Чат» и обеспечить открытие и закрытие диалога независимо от обновления счётчика. Проверить видимую карточку и состояние брокера после Escape, явного ответа и таймера.

Для ZM-018 ограничить ожидание ответа и блокировать кнопки только для конкретного запроса. При сбое проверить состояние в ядре перед повторной отправкой решения. Убедиться, что истечение старого запроса не блокирует следующий.

## 1. Основная корректность — ZM-003/004/005 (P1)

1. Унифицировать статусы агента, строки чата, истории и поиска. Приоритет: явный `status`/`verifiedStatus`, далее совместимое чтение старой записи; «не проверено» никогда не понижается до «выполнено».
2. Разделить событие «остановку запросили» и финальное `done`. Для инструмента, который ещё работает, показывать «остановка запрошена; ожидаю результат». Сохранять финальный реальный результат инструмента, если он вернулся после stop. Пока он не завершён, не запускать второй ход поверх него.
3. Для повторной попытки учитывать уже прошедшие шаги. Если отправка/удаление/запись могла произойти, сначала сверять состояние; не повторять всю фразу по одному клику без понятного предупреждения.

## 2. Согласовать обещание настроек — ZM-002 (P1)

Выбрать один продуктовый вариант: тема и внешний вид работают на всех разделах Nox, либо экран честно объясняет область действия текущих контролов. После выбора обновить CSS-токены так, чтобы фактический `.app`, поверхность, акцент, шрифт и сфера читали ожидаемые значения. Уточнить, какой именно параметр управляет цветом сферы.

## Вход и аккаунт — ZM-020/021/022 (P1/P2)

- Распространить таймаут входа на чтение тела ответа. После ошибки показать причину и вернуть доступ к кнопке.
- При временной недоступности аккаунта сохранить доступ к выходу и показать причину с возможностью повторить запрос.
- Исключить фон за формой первого запуска из навигации клавиатурой. Переносить фокус в чат после входа.

## 3. Журнал и раскрытие данных — ZM-006/007/008 (P2)

- Подключить экран истории к `journalSearch`, добавить offset/следующую страницу и показывать общее количество найденных строк.
- При остановке переводить активные карточки в явное конечное состояние, не оставлять «выполняется».
- Ввести единый безопасный formatter аргументов для подтверждений, строк действий, истории и подсказок; не полагаться на маскировку только при записи на диск.
- В ZM-014 восстановить кнопку «Вниз» при уходе с конца ленты и пересчитывать положение после окончательной отрисовки ответа.
- В ZM-015 согласовать ограничения экспорта и импорта. Сообщать о недопустимом пакете до записи или разбивать его на импортируемые части.
- В ZM-016 ограничить число одновременно построенных строк, сохранить поиск по всему каталогу и проверить задержку первого кадра после ввода.
- В ZM-017 добавлять в черновик только выполненные шаги. Сверять статус по идентификатору запуска и вызова, а доступность шага проверять до добавления.
- В ZM-019 сохранять принятую реплику до вызова модели и восстанавливать пометку о прерванном ходе в чате без повторного выполнения.

## 4. Доступность и полировка — ZM-009/010/011/012 (P2/P3)

- Поднять контраст мелких пояснений и placeholder до порога обычного текста.
- Уважать Windows `prefers-reduced-motion` сферой Nox, если владелец явно не включил отдельное осознанное исключение.
- В предпросмотре импорта показывать человеческое резюме изменений; сырой diff оставить только в дополнительном раскрываемом просмотре.
- Выравнять редактор команд в свободной области и повторно проверить 960×640 и 1200×720.

## Выход из блокера

Сначала исправить ZM-001 и повторить безопасный тест misbinding. Затем исправить статусы и stop race. Только после этого повторить оба `node --test`, живые QA трёх разделов и ручной сценарий, в котором владелец сначала отклоняет действие, затем подтверждает действие с другим аргументом. Платный API для этих тестов не нужен.
