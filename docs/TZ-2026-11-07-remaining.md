## 3.1. Мои решения по спорным местам (не пересматривать без меня)

1. **Оплата** — не реализуется и не подключается ни в одной задаче. Запрет всегда.
2. **Питомец** — только декоративная анимация без «показаний» и без данных из сети; виджет не должен изображать факты.
3. **Опасные клавиши** — `alt+f4`, `ctrl+alt+delete`, `win+r` в белый список не добавляем, даже если так «удобнее».
4. **MCP-серверы** — из каталога ничего не устанавливаем и не запускаем без моего отдельного согласия; непроверенные записи остаются `verified:false`.
5. **Данные владельца** — снимки экрана и содержимое окон не сохраняются на диск, не отправляются никуда, кроме вызова модели по текущей задаче.
6. **Красота не важнее честности** — если функция работает частично, это должно быть написано в отчёте и в подписи интерфейса, а не спрятано.

### ТЗ-2 (task-10). Прикрепить чужое окно: snap по заголовку

**Проблема.** Образцы «Окно влево/вправо/развернуть/свернуть» жмут `win+стрелки`. Из чата передним обычно остаётся окно Nox, поэтому двигается оно, а не нужное окно. У конкурента (Luxify) это работает по названию программы.

**Требования.**
1. Новый инструмент `windows_snap` в `src/tools/windows.js`: параметры `{ title?, side: 'left'|'right'|'maximize'|'minimize'|'center' }`. Движение — Win32 (`SetWindowPos`/`ShowWindow` через PowerShell `Add-Type`) или существующий механизм; `title` — часть подписи окна из `windows_list`.
2. Без `title` — двигать предыдущее окно, **если** его можно определить надёжно (не окно Nox, не панель задач, не оболочка); иначе честный отказ с просьбой назвать окно. Не угадывать.
3. Безопасность: окна Nox по pid не трогать, ничего не закрывать, чужие процессы не менять. Риск `T1`. `verify` читает новое положение/состояние окна: подтверждено/не проверено/ошибка — без выдуманного успеха.
4. Образцы «Windows» в `src/commands/samples.js`: «окно влево/вправо/развернуть/свернуть вниз» перевести на `windows_snap`; `win+стрелки` оставить только как запасной путь, если инструмент недоступен.
5. Обновить `tests/sample-protocols.test.js` и тесты окон.

**Файлы:** `apps/jarvis-desktop/src/tools/windows.js`, `apps/jarvis-desktop/tests/windows-arrange.test.js` (или новый `tests/windows-snap.test.js`), `apps/jarvis-desktop/src/commands/samples.js`, `apps/jarvis-desktop/tests/sample-protocols.test.js`.

**Критерии приёмки:**
- `node --test tests/windows-arrange.test.js tests/windows.test.js tests/sample-protocols.test.js` — зелёные;
- в отчёте: как выбирается окно без `title`, что происходит при отсутствии подходящего окна, ограничения (несколько мониторов, DPI, свёрнутые окна);
- живьём: назвать окно (например, Блокнот) — окно реально встаёт в половину экрана; без названия — или двигает предыдущее неноксовское окно, или честно отказывает.

### ТЗ-4 (task-12). «Учёба»: обвёл область экрана → объяснение

**Проблема.** У конкурента (Luxify) есть сценарий «непонятная задача на экране — обвёл и он объяснил». У нас этого нет.

**Требования.**
1. `src/screen/region.js` — чистые функции без ввода-вывода: проверка прямоугольника (границы экрана, минимальный размер, целые координаты), приведение к границам, человеческое описание области.
2. Инструмент снимка выбранной области (Electron `desktopCapturer` + `nativeImage.crop`): получает картинку области и отдаёт её модели по существующему пути картинок (как `screen_look`/`image_look`). Риск `T1`; `verify` — снимок получен и размеры совпали; иначе честная ошибка.
3. Окно: режим «объясни, что я обвёл» — выделение рамкой мышью, отмена по Esc, после выбора область уходит в чат с вопросом «что это и как решить».
4. Правила продукта: только объяснение, ничего не оплачивать и не нажимать; снимок не сохранять на диск без просьбы; в фоне, командах и Telegram инструмента нет.
5. По правилам карты: новый файл — строка в `AGENTS.md`, подпись в `TOOL_TITLES` (`renderer/shared.js`), слово в `TOOL_WORDS` (`src/deals/deals.js`), правило в `SYSTEM_PROMPT` (`main.js`). `AGENTS.md` правит Lead — согласовать.
6. `main.js` и `renderer/app.js` меняются только для подключения режима; политику и запреты не трогать.

**Файлы:** `src/screen/region.js` (новый), `src/tools/screen.js`, `tests/region.test.js` (новый), `tests/screen.test.js`, плюс точки подключения в `main.js`/`renderer/app.js`/`renderer/shared.js`/`src/deals/deals.js` — по согласованию с Lead.

**Критерии приёмки:**
- `node --test tests/region.test.js tests/screen.test.js` — зелёные;
- `node --check` изменённых файлов чистый;
- запуск окна с временным профилем не падает;
- в отчёте: ограничения (DPI, несколько мониторов, права экрана), что именно уходит модели и что не сохраняется.
