## Заход 1: глаза

## Заход 2: руки по id

- `desktop_click` (T1): id из снимка → перечитывает окно → проверяет, что элемент ещё тот → `ui_click` по имени и occurrence → пауза → снимок изменений.
- `desktop_type` (T1): ввод по id поля или в текущий фокус; после — снимок изменений.
- Если id исчез или окно сменилось — отказ и просьба сделать новый снимок. Вслепую не нажимает.
- `verify`: подтверждает нажатие/ввод по проверке самого `ui_click`/`ui_type`, иначе по дельте сцены; без доказательства — `unknown`.
- Долгие поручения: `desktop_observe`, `desktop_click`, `desktop_type` добавлены в `HANDS` (`src/missions/long.js`), чтобы автономная работа руками шла через тот же путь; класс риска не снижен.
- Тесты: 31 в `tests/perception.test.js`; полный набор приложения 1139/1139, сервер 16/16.

## Заход 3: память-петля

## Заход 4: обучение на опыте

- Опасные шаги (PowerShell, отправка, удаление, установка, команды) и разовые поисковые ходы навыком не становятся.

## Заход 5: длинные руки без упора в командную строку

- `runPowerShell` в `src/tools/system.js`: короткий скрипт идёт как раньше (`-EncodedCommand`), длинный — временным `.ps1` с BOM через `-File`.
- Причина: командная строка Windows ~32 767 символов; `ui_type` с текстом 2000 символов и `ui_click` с длинным именем падали `spawn ENAMETOOLONG` ещё до PowerShell.
- Временный файл удаляется после завершения, ошибки и таймаута.
- Живые проверки: скрипт 160 тыс. символов выполняется; `ui_type` с 2000 символов доходит до PowerShell и отвечает «окно не найдено» вместо `ENAMETOOLONG`; файл не остаётся.
- Тесты: 4 в `tests/powershell.test.js`.

## Заход 7: защита от чужих указаний и утечки секретов

- `src/policy/taint.js` — после текста со страницы, экрана, файла, буфера или MCP-сервера ход считается заражённым. Тогда исходящие действия (`mail_send`, `shell_run`, `browser_type`, `browser_open`, `url_open`, `clipboard_set`) в «Полном доступе» **спрашивают**, а не идут молча. Чтение и работа внутри остаются свободными.
- Заражение сбрасывается к следующему ходу; в длинных поручениях без владельца такое действие сразу **отклоняется**, потому что спросить некого.
- Секрет в исходящем аргументе (пароль, `sk-…`, `ghp_…`, приватный ключ) — отдельный вопрос в любом режиме. Проверка узкая, чтобы обычная команда `Get-CimInstance Win32_OperatingSystem` не считалась секретом.
- Оплата по-прежнему запрещена, удаление и установка спрашиваются: новые правила только добавляют вопросы, ни один запрет не ослаблен.
- Тесты: 7 в `tests/taint.test.js` (правила, цикл агента, сброс, секрет) и 3 проверки в `tests/long-tasks.test.js`.
- Полный набор: приложение **1190/1190**, сервер **16/16**.

## Заход 8: координаты и запасной клик мышью

- `ui_elements` теперь отдаёт координаты (`bounds`) каждого элемента: в запрос кэша UIA добавлено `BoundingRectangleProperty`, иначе поле приходило пустым.
- `src/perception/scene.js` сохраняет координаты и показывает их строкой `@x,y,w,h`; безымянная кнопка с координатами больше не выбрасывается из сцены.
- `desktop_click` при безымянном элементе или отказе `ui_click` нажимает мышью в центр координат. Для этого `mouse_click` получил `units=physical`: координаты UIA — настоящие пиксели, а не точки сжатого снимка экрана.
- Запасной клик идёт через тот же `desktop_click` (риск T1, очередь рук, перечитывание окна, снимок после), а не в обход политики. `verify` подтверждает изменение сцены.
- Тесты: сцена с безымянной кнопкой, отказ без `mouse_click`, нажатие по центру координат (`x=25, y=40`) — в `tests/perception.test.js`.
- Полный набор: приложение **1193/1193**.

## Заход 12: Mission Engine в отчёте, безопасная отмена и центр управления миссиями

Задача пришла шестью скриншотами (`ЗАДАЧА/`): список «Ещё 18 возможностей» и «7 функций», главное — Mission Engine. Разбор по каждой функции — в `FEATURES-18.md` рядом; здесь только сделанное в этом заходе.

- **Отчёт исполнителя отвечает на «что изменено, какие тесты, что осталось».** В `renderReport` добавлены разделы «Изменения в файлах» (только успешные вызовы инструментов, которые пишут файлы, с итогом проверки и путём резервной копии), «Тесты» (шаги с `code_test`; если запусков в фактах нет — так и написано, а не «тестов не было»), «Оставшиеся проблемы» (неподтверждённые критерии, непроверенные и незавершённые шаги, отказы мандата). Всё строится по фактам шагов; модель ничего не добавляет.
- **Безопасная отмена действий (№15).** Перед перезаписью файла `workspace_write` атомарно кладёт прежнюю версию в `backups/` рабочей папки (имя — время + хеш пути, до 50 копий, файл больше 8 МБ не перезаписывается без копии). Новый инструмент `workspace_restore`: `list: true` показывает копии, с `backup` возвращает прежнюю версию и сам подтверждает результат чтением. Защиты не ослаблены: перезапись вне `reports/` по-прежнему запрещена, папка программы и данных закрыта, пути копий ограничены `backups/`.
- **Центр управления миссиями (№18).** `src/tasks/board.js` — чистые функции строк и сводки; `missions:board` в `main.js` собирает задачи, строки внимания и отчёты; в окне появилась панель «Миссии» с кнопкой, сводкой («в работе, в очереди, ошибок, готово») и строкой «Открыть отчёт».

## Ограничения

- Живой E2E исполнителя сделан с scripted brain: механика (план, шаги, проверки, отчёт, восстановление, стоп) проверена на настоящем исполнителе, но без живых ключей модели.
- Живой клик выполнялся по безопасному пункту меню в Блокноте; клики по чужим приложениям, отправке и удалению не выполнялись.
- Заражение действует в пределах одного хода; после чужого текста руки спрашиваются/отклоняются до конца хода, на следующий ход пометка сбрасывается.
- Запасной клик по координатам проверен юнит-тестами и живым снимком; живое нажатие по безымянной кнопке в чужом окне не выполнялось.
- Повтор точной просьбы с сохранённым опытом уменьшил риск «забыть порядок», но на простой файловой задаче число вызовов модели не уменьшилось: модель и так делала 2 инструмента подряд.
- Резервные копии касаются только файлов, которые пишет `workspace_*`; отменить действие в чужом приложении по-прежнему нельзя.
- Панель «Миссии» живьём проверена на четырёх подложенных задачах во временной папке данных; на настоящей задаче исполнителя (через модель) в окне не проверялась.
- Расшифровки голосовых нет: в Windows не установлен языковой пакет распознавания речи; мост скачивает файл и честно просит написать текстом. Подключение расшифровщика — сразу, как только пакет установлен или появится разрешение на его установку.
- «Видеть» фото теперь означает два разных пути: `image_look` отдаёт модели само изображение (фото, схемы, графики), `image_read_text` — OCR-текст. Живой прогон с настоящей моделью не делался, поэтому качество описания конкретной фотографии в этой среде не проверено; границы (рабочая папка, 8 МБ, не PDF, без ссылок и junction) покрыты тестами.
- Просмотр видео недоступен: файл сохраняется и может быть переслан, но содержимое не анализируется.
- Отключение задачи `Hermes_Gateway` требует прав администратора: пока работает «сторож» автономной сессии; после её завершения Hermes сможет стартовать снова при следующем входе в Windows.
