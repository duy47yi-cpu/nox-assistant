# JARVIS PRO → Nox Assistant: карта поведения

**9 ноября 2026 · Windows · материалы V01–V15.** Цель — воспроизвести показанные сценарии в Nox для русскоязычного владельца ПК и подготовить их к выпуску. В кадре встречаются маркировка JARVIS PRO, AMBIONYS и в V04 отдельная подпись CODEXSSO. Единую версию или сборку по роликам установить нельзя. Старый разбор Luxify в `docs/superpowers/plans/2026-11-07-video-analysis.md` описывает другие материалы. Рабочие столы, каталог MCP и прочие функции Luxify не считаем требованиями этой подборки.

## Источники и границы

V01–V15 соответствуют файлам из сообщения владельца. Таблица содержит приблизительные таймкоды, основанные на выборке кадров примерно раз в три секунды и локальном распознавании звука. Визуальные изменения, утверждения диктора и предположения разделены. `video-index.txt` содержит длительности и SHA-256. Ролики — демонстрации с монтажом. Пакет, живой экземпляр и сетевой захват референса не предоставлены. Для MP4 использованы кадры и звук, у REA нет подходящей операции для этого формата. Внутренний стек, API, разрешения, причины ошибок и стабильность референса остаются неизвестны. XAML на экране V07 — содержимое рабочего окна, сам по себе он не доказывает стек ассистента.

## Компоненты и данные

- S01/S03/S06: шар и маленький индикатор из единого состояния, текстовый статус, таймер, кнопка стоп, согласование конкретного действия.
- S01/S02/S05: форма ввода, волна, вложение, карточка результата, сообщения, список истории, сворачиваемая таблица и ссылки.
- S04: выбор микрофона, режимы доступа и слушания, фон, цвета, прозрачность, масштаб, анимация, предпросмотр.
- S06/S07/S08/S09: цель действия, источник, время наблюдения, статус каждой попытки, миниатюра области только при разрешённом хранении.
- **Уверенность высокая по видимому контракту:** диалог → сообщения, сообщение → вложение, задача → файл, настройки → профиль оформления. По реальному формату хранения данных уверенности нет.
- **Модель Nox, вывод из сценариев:** ход → действия → подтверждение/результат, ход → свидетельства; стабильная цель окна и ключ повтора; файл → проверка формата. Это предложенные сущности, схема оригинала неизвестна.

## Как читать матрицу

В `features.csv` статус `code` означает, что в Nox найден профильный код. `partial` — есть основа, остался конкретный разрыв. `no` — специализированный сценарий не найден. `unverified` — требуется замер. `skip` — за пределами плана. Ни одна отметка не выдаётся за пройденную приёмку.

## Приоритет и завершённость анализа

M1–M5 в плане закрывают все десять потоков, с ранним выпуском основных функций. Размер L для устойчивого покрытия всех сценариев. Три трудные части: устойчивое управление внешними окнами и проверка, локальный доступ к чувствительным данным и отправке, низкая нагрузка при голосе/видео. Публичные счётчики, числа пользователей, конкретные модели распознавания, внешний вид персонажа и показатели ресурсов не считаем воспроизводимыми свойствами. Для выяснения реализации нужен точный пакет с разрешением на анализ или работающий экземпляр. Для проектирования Nox это не препятствие.
