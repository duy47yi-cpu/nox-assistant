# MIT desktop-assistant component donors

Scope: GitHub code donors relevant to the existing Nox Assistant architecture (Windows + Electron/Node, with existing voice, desktop control, tools, approvals, verification, MCP, workspaces and memory). Star counts below are the GitHub counts observed on 2026-11-08; they change. License checked from the repository's GitHub license badge or LICENSE/README where noted. This is a source review, not a code audit.

## Which low-profile MIT repositories contain components worth inspecting?

### Takeaway

The strongest immediate code-reading targets are **GhostHand** (typed Windows UIA actions, independent safety/confirmation, re-read-and-verify), **Wyzer** (typed tools, evidence-based task completion and focused-window checks), **xarmaq/Jarvis** (Russian voice + screen grounding + dynamic-island UI), and **ScreenAssistant** (a compact Win32 hotkey → screen capture → native OCR → overlay path). They are all MIT and below 100 stars; their implementations use C#/Python/Tauri rather than Nox's Node/Electron, so cherry-pick algorithms and patterns, not whole apps. [GhostHand](https://github.com/dushyantzz/Ghosthand), [Wyzer](https://github.com/XtraWyze/Wyzer-AI), [xarmaq/Jarvis](https://github.com/xarmaq/Jarvis), [ScreenAssistant](https://github.com/Satyam1616/ScreenAssistant)

### Cited Findings

- **GhostHand — 55 stars, MIT; best donor for desktop-control safety.** Windows-native .NET 8/WPF. It reads Windows UI Automation controls, asks a decision model to select among a deterministic finite set of candidate actions, executes via UIA patterns, re-reads the target and verifies the effect. Irreversible verbs require confirmation; password/token/card fields are redacted; password-manager apps are denied; actions are locally audited; Ctrl+Win/Esc/Stop cancel. Inspect `windows/` and especially the README's described loop, tests (`dotnet test windows/GhostHand.sln`), and `windows/src/GhostHand.App/`. Nox already has a richer policy/effects layer, but GhostHand is a very direct reference for candidate enumeration, UIA-first execution, risk boundaries and kill-switch behavior. It relies on Vercel AI Gateway/Jev, so its intent service is not local; the README lists 71 unit/integration tests. [Repository and MIT badge](https://github.com/dushyantzz/Ghosthand), [README: safety, architecture and test command](https://github.com/dushyantzz/Ghosthand/blob/main/README.md)

- **Wyzer — 3 stars, MIT; strongest donor for verified agent-task flow.** Windows/Python, Ollama, typed registered tools, native tool calling. Every planned step has explicit success criteria and tool evidence; it refuses to report completion while a step remains unverified. Its `ToolRegistry` is the model-visible tool catalog and uses Pydantic argument models; approval is bound to the validated tool name and arguments and expires. Inspect `wyzer/`, `tests/`, `docs/`, `evals/`, `examples/wyzer_example_pack/`; README also says focus-sensitive keyboard/clipboard actions check the expected target window immediately before input. This maps closely to Nox's `src/agent/effects.js`, mandate/criteria and policy work, though existing Nox code may already be stronger. [Repository, MIT badge and folders](https://github.com/XtraWyze/Wyzer-AI), [README: tool/evidence/approval design](https://github.com/XtraWyze/Wyzer-AI/blob/main/README.md)

- **xarmaq/Jarvis — 0 stars, MIT; best voice + screen + presence reference.** Windows 11, Python core, React/Tauri shell; Russian/English wake words, Silero VAD, GigaAM STT, streamed Qwen TTS, UI Automation, Windows OCR, screenshot grounding, browser control, activity cards and a dynamic island. README maps useful modules directly: `core/ears.py`, `core/turn.py`, `core/stt.py`, `core/resolve.py`, `core/brain.py`, `core/reflexes.py`, `core/hands.py`, `core/eyes.py`, `core/grounding.py`, `core/mouth.py`, `core/activities.py`, `island/src/`, `island/src-tauri/`. Good concepts for Russian voice and the Nox hands/observe/orb lanes. **High caution:** author labels it experimental; root reports only 2 commits; setup currently assumes an NVIDIA GPU/CUDA for TTS; README says `CONFIRM_DANGEROUS=False` by default and lists PowerShell/message/file actions. Read the policy and action implementation before borrowing. [Repository, 0 stars and MIT badge](https://github.com/xarmaq/Jarvis), [README: architecture, files and cautions](https://github.com/xarmaq/Jarvis/blob/main/README.md)

- **J.A.R.V.I.S-OS — 2 stars, MIT; candidate for system composition and evidence practices.** Local-first Windows assistant with offline wake word/STT/voice, Ollama, Windows OCR, file search, window controls and reminders; supports English and Kiswahili. README says a window-close action is confirmed after closing and reports failure if it did not take effect. Root includes `jarvis_os/`, `plugins/`, `docs/`, `tests/`, and `ARCHITECTURE.md`; 154 commits. Worth inspecting the newer implementation, especially plugin/policy/testing. Attribution/licensing needs care: README says this began as a fork of `ColeHacker381/J.A.R.V.I.S.` and preserves Mark 5 material; the repository notes `etext` as a separately licensed component. Do not assume the whole tree or vendored/legacy components are covered by a single MIT grant. [Repository, 2 stars and MIT badge](https://github.com/PHENOMVALENCE/JARVIS-OS), [README: features, verification and upstream notice](https://github.com/PHENOMVALENCE/JARVIS-OS/blob/main/README.md)

- **win-computer-use — 1 star, MIT; small Windows desktop-control toolkit.** Python package/CLI usable against Win32, WinForms, WPF, Qt, Electron and UWP. Inspect `win_computer_use/`, `scripts/`, `references/`, `SKILL.md`. Exposes full/region screenshots, mouse/keyboard, window listing/activation, UIA control lookup by name/type/automation ID, text entry, OpenCV template matching, RapidOCR/Tesseract, emergency-stop and failsafe. Nox already has corresponding observe/click/type tools, so the donor value is its CLI/tool interface, UIA selectors, image-match fallback and stop patterns; direct integration would mean adding Python/native dependencies. [Repository, 1 star and MIT badge](https://github.com/CarlosShao/win-computer-use), [README: capabilities and command reference](https://github.com/CarlosShao/win-computer-use/blob/main/README.md)

- **Vesper — 1 star, MIT; useful voice/intent/routine system to compare.** Windows/Python assistant with locally detected wake word and STT, instant offline pattern matcher, fallback between Groq/Gemini, about 60 tools, learned phrasings, routines, Piper/Kokoro speech, tray and live-transcript orb. Inspect `vesper/` and `scripts/`. Specifically compare its fast paths and provider failover against Nox's shortcuts/deals/tiers, and its timings/journal/controls against Nox's voice and event flow. Root showed only 2 commits despite broad README claims, so treat as an implementation lead and inspect tests/code depth before relying on it. [Repository, 1 star and MIT badge](https://github.com/Awakelol/vesper-assistant), [README: capabilities/config/commands](https://github.com/Awakelol/vesper-assistant/blob/main/README.md)

- **ScreenAssistant — 3 stars, MIT; focused reference for screen-question overlay.** C#/.NET 8 Windows app; `Services/HotkeyService.cs` registers Win32 hotkeys, `CaptureService.cs` captures via GDI, `OcrService.cs` uses `Windows.Media.Ocr`, `LlmService.cs` streams Ollama/OpenAI-compatible output, and `UI/OverlayWindow.xaml(.cs)` renders an arrow-key overlay; setup/tray wiring is in `UI/SetupWindow.xaml(.cs)`, `App.xaml.cs`, `Services/StartupService.cs`. Strong isolated pattern if improving Nox screen capture/ocr and a keyboard-driven on-top panel. **Caution:** only 1 commit, and `cloud.key` is tracked as a placeholder; the author explicitly warns that any baked key can be extracted and says the tracked file is only a placeholder. It is not a reason to copy its key/config approach. [Repository, 3 stars and MIT badge](https://github.com/Satyam1616/ScreenAssistant), [README: exact file map and credential warning](https://github.com/Satyam1616/ScreenAssistant/blob/main/README.md)

- **jarvis-ai-assistant (accountnowe) — 3 stars, MIT; simple offline-voice composition.** Windows/Python, Ollama, Whisper/openWakeWord, pyttsx3, SQLite memory, animated GUI and actions for apps/files/PDF/power/volume/brightness. Inspect `audio/`, `brain/`, `actions/`, `utils/`, `tests/`, `gui.py`. Good for a small end-to-end example of where action modules, voice and memory can live. Only 4 commits; README describes network-backed search/weather alongside the "offline-first" positioning, so verify actual egress and tests rather than importing broad privacy claims. [Repository, 3 stars and MIT badge](https://github.com/accountnowe/jarvis-ai-assistant), [README: structure/features/license](https://github.com/accountnowe/jarvis-ai-assistant/blob/main/README.md)

- **Jarvis_AI-Asistan — 0 stars, MIT; Turkish local-assistant implementation.** Windows 11/Python/PyQt6, local Whisper, Ollama, Piper/pyttsx3, model selection by task, animated transparent overlay and confirmation for power controls. Inspect `core/`, `modules/`, `ui/`, `tests/`, plus the Turkish documentation. Potential donor for local model routing and an overlay, but only 5 commits and its command/TTS assumptions are Turkish; likely lower signal than Wyzer and xarmaq. [Repository, 0 stars](https://github.com/Ibrahim-Taskiran/Jarvis_AI-Asistan), [README: MIT, features and root folders](https://github.com/Ibrahim-Taskiran/Jarvis_AI-Asistan/blob/master/README.md)

- **RustBuddyAI — 8 stars, MIT; Rust sidecar sketch for local hotkey/voice.** Windows-native Rust alpha with global hotkey → audio capture → local whisper-rs → local DeepSeek/Ollama endpoint → parsed intent → executor/voice feedback. Inspect `buddy/src/main.rs`, `audio.rs`, `transcription.rs`, `intent.rs`, `executor.rs`, `feedback.rs`, and `config.rs`. Only useful if exploring a Rust helper for always-on input; README calls it v0.1 MVP and explicitly says there is no wake-word detection yet. Its configured system actions include shutdown/restart, so inspect execution gating. [Repository, MIT badge, 8 stars and file tree](https://github.com/cschladetsch/RustBuddyAI), [README: architecture and paths](https://github.com/cschladetsch/RustBuddyAI/blob/master/Readme.md)

- **Project Aether — 0 stars, MIT; high-feature local/MCP reference, but large scope.** Windows/Python local Ollama models, GDI/window perception, openWakeWord, Whisper, overlay, FastMCP tool servers, intent routing, dynamic tool masks, human approval for mutation, tracing, context budgets and terminal sandbox. Inspect `src/`, `tests/`, `evals/`, `docs/`; the README names `src/voice/overlay.py`, and describes separate screen/calendar/email/Obsidian/weather MCP servers. It has 15 commits. Good architectural idea source for MCP boundaries, voice activation and split model routing; don't treat the advertised “100% local” wording as sufficient proof: the same README lists Microsoft Neural Edge-TTS, which should be checked for network use. [Repository, 0 stars and MIT badge](https://github.com/jrnai/aether), [README: architecture/components](https://github.com/jrnai/aether/blob/main/README.md)

### Inferences

- **Best order to inspect first:** (1) GhostHand for deterministic UIA candidates, risk gating and verify-after-action; (2) Wyzer for tool schema/evidence/approval and task finish criteria; (3) xarmaq for RU voice and island; (4) ScreenAssistant for native OCR/capture/overlay; (5) JARVIS-OS for broad system design and mature plugin/testing structure. This order is based on overlap with the gaps implied by Nox's documented architecture, not a code-quality audit.
- There is little reason to copy another assistant wholesale: Nox already documents equivalent or more developed subsystems for voice, policy, desktop control, memory, MCP and result verification. Highest leverage is likely narrow pattern comparisons against current source and a donor-attribution/license record for any copied file.
- MIT at repository level does not grant ownership of model weights, voice samples, downloaded models, fonts, datasets, or third-party packages. xarmaq and JARVIS-OS explicitly mention separate asset/third-party terms; audit those per artifact before bundling.

### Gaps

- I did not inspect or execute source code; file/path recommendations are derived from repository maps and README documentation. Every selected module still needs source review for bugs, security boundaries, stale dependencies and whether the README matches implementation.
- Star counts are a point-in-time observation and can change. Nox's current implementation was not opened during this delegated component scan; relevance is based on the supplied project map.
- Public Reddit/other-community discussion is being covered separately; this note is GitHub-only.

## Which tempting repositories should not enter an MIT donor list?

### Takeaway

Several very relevant repos fail the MIT condition. Keep the license filter strict; an attractive assistant UI does not make the code legally reusable under MIT.

### Cited Findings

- **VoiceClaw is proprietary (6 stars), not MIT.** Its tracked `LICENSE` explicitly says proprietary and prohibits copying, modification, merging and derivative works without permission, notwithstanding how interesting its README's tiered routing, plugins, hotkeys and learning features may be. Exclude. [Repository](https://github.com/AryanGonsalves/VoiceClaw), [LICENSE text](https://github.com/AryanGonsalves/VoiceClaw/blob/main/LICENSE)
- **Nova.Ai is GPL-3.0 (0 stars), not MIT.** It has an Electron/JavaScript app and Python backend with orb, audio, router and safety filters, but GitHub identifies GPL-3.0. Exclude from an MIT-only donor pool unless Nox intentionally accepts GPL obligations after legal review. [Repository and GPL badge](https://github.com/Click2x/NovaAI), [LICENSE](https://github.com/Click2x/NovaAI/blob/main/LICENSE)
- **Greninja-Personal_Assistant is an interesting Windows/Tauri voice-control system but no MIT license was visible during this check.** Do not infer permission from public source availability; exclude until a valid license is confirmed. [Repository and root files](https://github.com/Greninja110/Greninja-Personal_Assistant)

### Inferences

- A missing license file and a proprietary/GPL license are materially different cases, but neither belongs in a shortlist marked “MIT-only.”

### Gaps

- I did not inspect every file or dependency of the repositories above, and repository-level license badges do not automatically establish the terms for bundled models/assets. Inspect any candidate's LICENSE, `NOTICE`/third-party notices, and files selected for reuse.
